## Description

## Problem
Catalog scans already rotate the first product processed on each run, but existing-negotiation checks always start from MAIN and then walk additional products in a fixed order. In controlled real-action mode the global next-step cap is 1 per check, so an actionable conversation near the front of the list can repeatedly consume the only real-action slot and starve later products indefinitely.

## Changes
- rotate negotiation product priority independently per bot across checks
- keep one shared per-run quota across all products
- preserve MAIN-only legacy behavior for single-product bots
- cover MAIN + 4 active additional products + 1 inactive negotiating product
- verify rotation state is independent per bot

## Safety
Only processing order changes. Product-scoped listing reads, negotiation strategy selection, action guards, backend daily quota, and the global per-check real-action cap remain unchanged.
