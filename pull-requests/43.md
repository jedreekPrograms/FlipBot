## Description

## Why
A production CATALOG_SCAN could find several good listings but start only one negotiation. Older DISCOVERED listings were then considered again only if they still appeared in the current newest-first catalog page, so valid offers could fall out of the page and remain stranded forever.

The latest runtime log also exposed a target-matcher false negative: `Samsung Galaxy S25 SM-S931 12/128GB Enterprise Edition Srebrny` was rejected as if `S931` were a competing Samsung model, even though it is a manufacturer product code.

## What changed
- process the full persisted DISCOVERED backlog instead of intersecting it away with only the current scan
- preserve newest-first priority while guaranteeing backlog progress with a 3-fresh : 2-backlog ordering
- keep backlog oldest-first so it drains deterministically
- continue to apply price guard, target checks, mandatory full-title verification, availability/offer-action checks, persistent FIRST_OFFER guard and quota before submit
- allow several confirmed first offers in one production CATALOG_SCAN instead of returning after the first success
- continue past candidate-local failures that happen strictly before guard/quota/submit; guard refusal and ambiguous post-quota failures still fail closed
- add production throughput env vars:
  - `FLIPBOT_MAX_REAL_OFFERS_PER_CATALOG_SCAN` default 3, range 1..5
  - `FLIPBOT_MAX_REAL_NEXT_STEPS_PER_CHECK` default 1, range 1..5
- controlled mode remains hard-capped at one action regardless of those env vars
- fix Samsung `SM-Sxxx` technical product codes so they do not conflict with marketing model keys such as `S25`, while still rejecting S24, S25 Ultra, etc.
- update runtime logging/docs

## Tests added
- backlog/current-scan fairness and empty-current-scan backlog draining
- Samsung S25/S25+/S24/Ultra matcher regressions
- production vs controlled action-limit behavior and limit parsing

## Preserved safety invariant
The backend's current global marketplace `listingId` claim remains unchanged, so multiple bot accounts still cannot independently claim the same Vinted listing.
