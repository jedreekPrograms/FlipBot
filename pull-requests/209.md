## Description

Third resource-audit step. Scale worker-slot capacity down as well as up when RUNNING bot count changes.

Behavior:
- target slot count remains min(RUNNING bots, configured workerCount)
- surplus slots receive a graceful retirement request instead of Future.cancel(true)
- an idle slot notices retirement within about one second
- a slot that already claimed a task finishes that task and only then exits
- browser cleanup stays on the owner worker thread
- scale-up continues to recreate required capacity

Tests cover 10 -> 3, 3 -> 10, unchanged capacity, invalid counts, and prompt idle retirement.

No bot schedule intervals, offer/negotiation semantics, browser session persistence, market-stats or frontend behavior is changed.
