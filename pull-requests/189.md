## Description

## Problem
The production scheduler already uses `MultiProductExistingNegotiationProcessor`, but the legacy/manual `BotWorker` used by `TestApplication` still instantiated the unscoped `ExistingNegotiationProcessor`. Because that worker can execute real next steps, a manual run with additional products could inspect all negotiating listings while the bot context still contained the MAIN configuration.

## Change
- switch the legacy worker to the same `MultiProductExistingNegotiationProcessor` used by the scheduled runtime
- keep the existing shared quota, real-action limits, catalog processor and worker lifecycle unchanged

## Scope
This is intentionally a minimal compatibility fix: one processor substitution plus its import. The existing multi-product processor already has coverage for target isolation and negotiation priority rotation.
