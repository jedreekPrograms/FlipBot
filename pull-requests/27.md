## Description

## What changed
- stack pricing brand sections vertically instead of horizontally
- make each brand header clickable/collapsible while preserving the existing visual style
- add per-model columns: offers from the last 7 days, recommended bot count, and existing production bot count
- recommended bot count uses `ceil(offersLast7Days / 35)` (5 new conversations/day * 7 days per bot)
- exclude the dedicated market-statistics observer from production bot counts

## Market statistics architecture
- add V19 storage for per-model scan state and marketplace listing observations
- record first-seen / last-seen marketplace listing IDs independently from negotiation listings
- first complete scan creates a baseline and does not count existing offers as new
- after baseline, rolling 7-day supply is based on non-baseline IDs first observed during the last 7 days
- UI intentionally shows `Zbieranie danych X/7 dni` until a full 7-day window exists instead of inventing a historical estimate
- zero-offer scans are valid and can complete a baseline
- bounded baseline seed prevents crawling the entire historical Vinted catalog for very popular models
- later scans are marked incomplete if they hit the configured safety limit before reaching a known-listing boundary

## Dedicated collector
- add a separate single-thread market-statistics runtime, independent from normal bot worker slots
- collector uses one designated STOPPED observer account and marks it as `market_stats_observer`
- collector is disabled by default and requires `FLIPBOT_MARKET_STATS_ENABLED=true` plus a positive `FLIPBOT_MARKET_STATS_BOT_ID`
- default interval is 24 hours and headless mode is true
- collector applies newest-first search, brand and resolved category when available, then reuses the existing strict title/URL target matcher
- if no unique production category can be resolved for a model, collector falls back to brand + text search with conservative accessory filtering
- collector uses known listing IDs as a boundary, so normal daily runs scan only new listings plus a small known tail instead of opening every offer

## Safety
- no negotiation processor, real-action guard, quota, one-shot, or submit logic was changed
- collector never instantiates `NewNegotiationProcessor` or any real-offer executor
- collector has its own BrowserManager/thread and cannot consume normal scheduler worker slots
- observer account must remain STOPPED, preventing it from sharing a Playwright session with the normal scheduler
- feature is disabled by default until an observer account is explicitly configured
