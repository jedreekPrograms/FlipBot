## Scope

This is a behavior-preserving cleanup after the latest locally-added frontend files landed on `main`.

### Frontend structure
- split the 1153-line `HistoryPage` into a small page orchestrator plus focused history toolbar, status filters, card, types and pure utilities
- preserve history filtering, sorting, counts, price/discount calculations, date formatting and Vinted URL normalization
- replace the two newly introduced native selects (History and Offer Strategy) with the shared `AppSelect` from the responsive UI refactor
- simplify `OfferStrategySection` without changing the first-offer safety behavior

### API layer
- extend the shared API error utility with a reusable `assertApiResponse`
- preserve JSON `{message}` errors and useful `text/plain` backend errors while avoiding raw HTML error pages
- remove duplicate response/error parsing from bots, dictionaries, observer, listings, dashboard, history, commands, credentials and market-stats clients
- preserve endpoint-specific 400/404/409 behavior where it carries domain meaning

### Repository hygiene
- remove unused Vite starter `frontend/src/App.css`
- remove already-ignored `docker/.idea` metadata that was still tracked in Git

### CI
- add GitHub Actions checks for:
  - frontend `npm ci`, lint and production build
  - backend Maven tests with PostgreSQL 17 service
  - Playwright-module Maven unit tests
- CI does not start browsers or execute any real Vinted actions

## Safety
- no backend business logic changed
- no database migrations changed
- no Playwright production/negotiation code changed
- no real-action flags, offer limits or submission behavior changed

## Review focus

Final review notes before merge:

- CI is green for all three jobs: frontend lint + production build, backend context/JPA test on PostgreSQL 17, and Playwright Maven tests.
- The frontend build transformed 67 modules and completed successfully after the History extraction and shared-select/API changes.
- The CI setup exposed an existing schema-management debt: a completely empty database cannot replay Flyway from V1 because the migration chain assumes Hibernate-created base tables already exist. This PR intentionally does not invent a risky historical baseline. Backend CI therefore verifies mappings/context on an isolated Hibernate `create-drop` schema with Flyway disabled.
- Recommended separate follow-up: create and verify a true Flyway baseline from the actual production schema, then move toward `ddl-auto: validate`.
- Large real-action Playwright classes (offer/negotiation/filter executors) were audited structurally but deliberately not mechanically split in this PR because current tests are too sparse to justify that regression risk.
- `npm ci` currently reports one high-severity dependency advisory. This PR does not run a blind `npm audit fix`; that should be identified and upgraded deliberately in a separate dependency change.
