## Description

## Problems confirmed from the latest runtime log

1. Bot 3 reaches category and Samsung brand correctly, but every `CATALOG_SCAN` fails while resolving the exact `Galaxy S25` model. The runtime reports 24-28 visible model rows, no exact label, then retries the catalog job.
2. The dedicated Market Stats observer reaches the Vinted e-mail form and submits it, but authentication does not complete. Because login happens before the target loop, that single failure currently prevents all 76 market-stat targets from being scanned.
3. Independent `NEGOTIATION_CHECK` jobs already continue correctly after a catalog failure; that scheduler isolation is preserved.

## S25 model-selection fix

- use plain-string `hasText(model)` only to narrow the current Vinted model list to likely rows; no unsupported regexp flags are involved
- keep final selection fail-closed: a row is accepted only after the exact requested model label is recovered
- inspect the selectable row plus visible `label`, `span`, and `p` descendants; fall back to `textContent`, `aria-label`, and `title` when row `innerText()` is empty
- preserve exact rejection of sibling variants such as `Galaxy S25 Edge`, `Galaxy S25 Ultra`, `Galaxy S25 FE`, and `Galaxy S25+`
- improve failure diagnostics with text-narrowing counts and actual partial labels
- avoid repeatedly interrogating every Samsung model row, which made the nominal 10-second model wait take far longer in production

## Market Stats observer fix

Market Stats is a read-only collector: it only visits the public catalog, applies filters, scans listing ids and records observations in our backend. It never submits offers or negotiation actions.

- authenticated observer login is still preferred
- if observer login fails for a non-interruption reason, collection continues in anonymous read-only catalog mode instead of dropping the whole daily pass
- after login failure the page is explicitly returned to the catalog before target scanning starts
- an anonymous context is never saved over the observer's stored session
- login failure remains clearly logged, including full details at DEBUG
- if anonymous Vinted access itself cannot scan a target, the existing per-model failure/retry handling still reports that transparently

## Safety / unchanged behavior

No negotiation, quota, real-submit, scheduler cadence, listing-target matching or pricing semantics are changed. A catalog failure still cannot delay the bot's independent negotiation checks.
