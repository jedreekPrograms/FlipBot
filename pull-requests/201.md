## Description

## What
- replace one executor task per async runtime event with a hard-bounded per-bot event buffer
- coalesce consecutive `QUEUED` updates to the newest schedule timestamp
- preserve event ordering through one serialized telemetry drain
- keep `SESSION_BLOCKED` synchronous and authoritative, with a short-lived per-bot barrier that prevents stale async events from overwriting COOLDOWN
- add buffer regression tests for coalescing, hard capacity and terminal -> queued ordering

## Why
`RuntimeTelemetryReporter` used an unbounded single-thread executor queue. If backend telemetry stalled, status events could accumulate without a memory bound. Backend HTTP requests are now time-bounded by #200; this PR also bounds the number of retained telemetry objects themselves without changing marketplace execution semantics.
