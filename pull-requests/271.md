## Description

## Problem

Vinted can migrate an older inbox route (for example UUID-like conversation id) to a newer numeric conversation id. In the observed failing negotiation, the page started on the stored conversation `01a0907b-ac02-72d6-8504-c97d3291a5c4`, then Vinted canonicalized it to `500035197835` with `referrer=/inbox/<old-id>`. FlipBot correctly prepared step 2, but the final fail-closed verifier treated the canonical id as an unrelated conversation and never clicked submit, causing the same offer to be prepared every negotiation check.

## Fix

- Add a strict `ConversationIdentityResolver`:
  - exact id remains valid;
  - a changed id is accepted **only** on trusted HTTPS `vinted.pl` and only when the final URL `referrer` proves it came from the exact stored conversation;
  - unrelated redirects remain hard failures.
- Add a narrow backend endpoint that updates only `conversationId` + `conversationUrl`; it does not touch price, step, status, activity clocks, formal-response timers, or decision state.
- Canonicalize conversation identity during normal conversation inspection and next-step preparation.
- Final prepared-state verification returns the canonical listing and carries it through submit/audit/backend update, so the old id cannot be written back after a successful canonicalization.
- Existing fail-closed action guard/quota behavior stays unchanged.

## Regression coverage

- Exact stored conversation is accepted.
- The real observed UUID -> numeric redirect form is accepted and canonicalized.
- Unrelated conversation/referrer is rejected.
- Non-Vinted URL is rejected.
- Backend canonicalization test proves negotiation state/timers are preserved.
