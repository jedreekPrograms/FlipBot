## Description

### Why
Fresh headed-runtime logs from 2026-08-22 showed three concrete UI regressions while the overall scheduler/observer startup remained healthy:

1. an exact Galaxy S26 model candidate was briefly exposed as `selectable-item-brand_collection-10632--title`, causing one catalog cycle to fail closed before a later retry recovered;
2. Vinted displayed the own-offer status `Anulowane`, which was stable but unsupported, so the conversation reader logged it every 500 ms for the full 20-second recognition timeout before the availability detector correctly marked the sold/removed item unavailable;
3. the first-offer sold-state probe used Java `Pattern.UNICODE_CASE`, which Playwright Java cannot serialize to a supported JS RegExp flag.

### Changes
- accept only the known Vinted `--title` child suffix when extracting an already-proven numeric model collection ID; arbitrary suffixes still fail closed and final `brand_collection_ids[]` verification is unchanged
- preserve unsupported visible own-offer status text in an UNKNOWN snapshot and return it immediately instead of polling the same stable label for 20 seconds
- keep UNKNOWN fail-safe: it cannot itself trigger a follow-up offer, while downstream availability checks still run
- remove unsupported `UNICODE_CASE` from the sold-label regex
- add regression tests for the S26 `--title` test-id, unsupported raw status preservation, and Playwright-compatible regex flags

### Safety
No quota, guard, idempotency, target-matching, or real-submit policy is relaxed. Exact Vinted model mode still requires exact visible label evidence and verifies the persisted collection ID end-to-end.
