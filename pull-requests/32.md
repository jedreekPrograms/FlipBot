## Description

## Problem

Po PR #31 observer dostał poprawne dictionary target semantics, ale jednocześnie zaczął twardo pomijać każdy legacy dictionary model bez przypisanej kategorii. W dostarczonym logu collector dostał 23 targety, przeskanował tylko 2 i pominął 21 modeli.

To łamie podstawowe założenie market observera: ma zbierać statystyki dla całego słownika modeli, a brak category metadata nie może oznaczać braku danych rynkowych.

Drugi problem: wyjątek pojedynczego modelu był łapany wewnątrz collectora, po czym cała runda i tak kończyła się jako `Collection completed`, więc `MarketStatsManager` planował następny scan dopiero za 24h zamiast użyć istniejącego 15-minutowego failure retry.

## Nowe zachowanie

### Model z poprawną kategorią
Zachowujemy dokładnie semantykę z PR #31:
- `VINTED_MODEL` -> category + brand + Vinted model + newest-first,
- `SEARCH_QUERY` -> text search + category + brand + newest-first,
- strict title/URL matcher przed policzeniem listing ID.

### Model bez kategorii
Observer już go NIE pomija.

Fallback:
- global text search po nazwie modelu,
- brand filter,
- newest-first,
- konserwatywne odrzucanie oczywistych akcesoriów,
- ten sam strict title/URL matcher przed policzeniem ID.

Fallback celowo używa `SEARCH_QUERY`, nawet jeśli dictionary model jest `VINTED_MODEL`, ponieważ filtr modelu Vinted wymaga wejścia w odpowiednią kategorię. Brak kategorii poszerza tylko etap discovery; nie poszerza kryterium zaakceptowania listingu.

### Pełność rundy
- collector nadal próbuje wszystkie targety nawet jeśli jeden model padnie,
- na końcu loguje `targets / recorded / globalFallback / failed`,
- jeśli choć jeden model faktycznie się nie przeskanuje, runda jest oznaczana jako incomplete przez wyjątek po zakończeniu pozostałych targetów,
- dzięki temu istniejący `MarketStatsManager` uruchomi retry za 15 minut zamiast udawać pełny sukces i czekać 24h.

## Safety

Zmiana dotyczy tylko `MarketStatsCollector`.

Nie zmienia:
- normalnych botów,
- negocjacji,
- real actions / guardów / quota,
- schedulera botów,
- backendowego zapisu statystyk,
- dictionary API,
- dokładnego targetowania modeli, które mają już poprawną kategorię.
