## Description

## Problem

The session-block scheduler itself correctly waits, but an earlier storageState restore-recovery path could remove `sessions/bot-X.json` from the active slot before the block/cooldown logic took over. That is how a recoverable session could disappear even though the intended behavior for `SESSION_BLOCKED` is simply to wait.

## Fix

- make session recovery strictly non-destructive
- when Playwright cannot restore a stored session, create a timestamped backup copy but leave the active `sessions/bot-X.json` untouched
- if a clean-context retry then reaches a Vinted session-block state, the original active session remains available throughout the cooldown
- fail closed if the safety backup cannot be written
- add regression coverage proving the active session survives one and repeated recovery attempts byte-for-byte

## Expected behavior

`SESSION_BLOCKED` now means exactly: persist the block episode, pause all jobs for the configured backoff, keep the active session file, and retry only after the scheduler allows it.

This PR does not shorten or bypass Vinted cooldowns and does not change access behavior; it prevents local session data loss.
