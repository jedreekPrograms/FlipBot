## Description

## Summary
- keep normal bot sessions fail-closed when a stored `bot-X.json` cannot be restored
- prevent the legacy `BotContext` recovery path from silently switching to `createContext(null)` after a storage-state restore failure
- leave the saved session file untouched so a transient Playwright restore problem cannot turn a logged-in bot into a fresh browser session
- preserve the original Playwright error as suppressed diagnostic information

## Scope
Only `BrowserManager` changes. Market observer, login logic, CAPTCHA handling, workers, negotiations, and session file format are untouched.

## Expected behavior
- normal bot with valid stored session: unchanged
- bot without any stored session: clean first-login context still works
- anonymous market observer: clean anonymous context still works
- existing stored session that fails to restore: the job fails instead of silently opening a clean context
