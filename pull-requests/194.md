## Description

## Problem
The application has Flyway disabled in the local runtime configuration, so `V40__snapshot_listing_product_provenance.sql` is not executed automatically. Existing databases upgraded to code that maps `listing.product_target_label` fail at runtime with PostgreSQL `42703: column ... product_target_label does not exist`.

## Fix
- extend `BotAdditionalTargetSchemaInitializer` to add `listing.product_target_label VARCHAR(1000)` with `IF NOT EXISTS`
- make V40 itself idempotent with `ADD COLUMN IF NOT EXISTS` so a future Flyway-enabled startup remains compatible with databases previously repaired by the initializer
- add a Spring Boot regression test asserting the provenance column exists with length 1000 after startup

## Safety
No negotiation, quota, session, Playwright, target-routing, or listing ownership behavior changes. This PR only repairs schema compatibility for existing databases.

Full repository CI is the merge gate.
