## Description

## Problem
A Playwright storage-state restore failure currently calls `SessionManager.invalidateSession()`, which physically deletes `sessions/bot-X.json`. This made bot #3 lose its recoverable Vinted session during the session recovery/backoff flow.

## Fix
- preserve unusable storageState files under `sessions/backups/` instead of deleting them
- prefer an atomic move, with a normal move fallback when atomic moves are unavailable
- fail closed if the session cannot be preserved, so clean-context recovery cannot overwrite the only copy
- keep the active session slot clear after successful quarantine so a genuinely broken storageState does not cause an endless restore loop
- add filesystem regression tests proving session bytes survive invalidation and missing sessions are a no-op

## Scope
This does not shorten or bypass `SESSION BLOCKED` cooldowns and does not change Vinted access behavior. It only makes local session recovery non-destructive.
