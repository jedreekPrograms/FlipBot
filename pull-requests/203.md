## Description

## What
- add `FLIPBOT_MARKET_STATS_BROWSER_RECYCLE_TARGETS` with safe default `3` (clamped 1..50)
- make the resumable target client return bounded rotated batches while preserving original global indices
- run successive existing `MarketStatsCollector.collectOnce()` batches so each batch gets its own BrowserManager/BotContext and closes it before the next batch
- preserve the existing traffic-backoff resume semantics using the current batch client's original target index
- add regression coverage for wrap-around batching, non-duplicate bounded batches, and recycle configuration

## Why
The market-stats observer previously kept one Chromium/context alive across the entire model pass, including many catalog/detail navigations. That was not a permanent leak, but it allowed one observer process tree to grow very large. Recycling after a few models bounds peak browser lifetime without touching the collector's listing/publication logic or production bot sessions.
