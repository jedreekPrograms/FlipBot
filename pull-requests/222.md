## Description

## What changes
- replaces per-second deferred catalog retry polling with capacity-aware job claiming
- due catalog work remains pending without occupying a worker while catalog capacity is full
- releasing a catalog slot wakes scheduler waiters immediately
- negotiations remain eligible while a catalog for the same bot waits for capacity
- oldest due work wins across bots; negotiations win ties/per-bot due conflicts so catalogs cannot permanently hide seller responses
- changes default negotiation cadence from 120s to 300s; catalog cadence stays 900s

## What intentionally does not change
- session files / SessionManager
- negotiation decision logic or real-action safeguards
- catalog filtering/model logic
- max catalog concurrency remains 3 by default

## Tests
- preserves polling/future-delay coverage
- proves blocked catalog does not occupy a worker
- proves newly active negotiation can run while catalog capacity is full
- proves released capacity hands off immediately without depending on legacy retry delay
- proves configured catalog concurrency is respected
