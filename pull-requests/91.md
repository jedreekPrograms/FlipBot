## Description

Stage 10 fixes one narrow PRICE_PROBE outcome-classification bug.

Finding:
- after the probe send click, `waitForComposerToClear()` treated a Playwright exception while reading the composer as positive delivery confirmation;
- losing access to the composer is not proof that the message was delivered, so the worker could report `SENT` when the marketplace outcome was actually ambiguous.

Fix:
- after a send click, a Playwright exception while checking the composer now returns `false` from the confirmation check;
- the existing caller therefore reports `UNKNOWN`, not `SENT`;
- backend semantics already keep UNKNOWN slots reserved and forbid automatic resend/retry, so this change is fail-closed and does not create duplicate probe messages.

Scope is deliberately minimal: one Playwright file, no selectors, no scheduler, backend, database, frontend, normal Vinted negotiation, quota, or guard behavior changes.
