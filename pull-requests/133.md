## Description

## Problem
Bot 4 correctly applied the exact Vinted `Galaxy S25` model filter, but after the current scan returned no genuinely new rows it processed two persisted `DISCOVERED` backlog entries with catalog identities `Samsung Galaxy Tab Active 3` and `Samsung Galaxy Tab S`.

The VINTED_MODEL guard considered those labels ambiguous because neither contains a compact model key such as `s24`/`s25`, so Playwright opened the live item pages even though the explicit `Galaxy Tab` family already proves they are not a Galaxy S25 phone.

## Fix
- treat the explicit Vinted model-family token `tab` as conclusive cross-family evidence when the configured model is not a Tab target
- keep generic seller wording such as `Tablet i ładowarka` ambiguous so we do not over-classify arbitrary titles
- preserve existing exact-model, variant and technical-code protections

## Regression coverage
- `Galaxy Tab Active 3` vs `Galaxy S25` => MISMATCH
- `Galaxy Tab S` vs `Galaxy S25` => MISMATCH
- existing `Galaxy Tab S9 FE+`, Fold/Flip, S24/S25 Ultra and generic-title behavior remains covered
- integration coverage through `ListingTargetMatcher`
