## Description

## What this fixes
- Cennik/model planning now counts only `FIRST_OFFER + CONFIRMED` rows from `real_action_audit` as newly started negotiations instead of counting every daily quota action (which also included `NEXT_STEP`).
- Negotiation capacity no longer reserves future slots for an active listing that is already superseded by another *active confirmed* marketplace owner.
- Keeps stale/terminal-owner cases fail-safe: the planner only ignores a row when another owner is still active, so a sole current conversation is not silently dropped.
- Adds a regression test for the duplicate-capacity case.

## Why
The database audit on 2026-08-31 showed `Galaxy S25` as 6 in the UI while the actual confirmed breakdown was 5 `FIRST_OFFER` + 1 `NEXT_STEP`. It also found legacy cross-bot duplicates that consumed planner capacity before the database cleanup.

## Safety
This PR does not loosen the global FIRST_OFFER ownership guard and does not auto-transfer terminal claims. The one-time legacy ownership cleanup was performed separately after a dry-run and protected-history validation.
