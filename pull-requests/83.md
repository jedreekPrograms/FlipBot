## Description

## Stage 3: reproducible database bootstrap

This replaces the historical Hibernate+Flyway mixed schema ownership with a verified Flyway baseline.

### What changes
- adds `B35__current_schema_baseline.sql` generated from the current PostgreSQL/Hibernate model plus the database-only invariants from V1..V35
- preserves durable `marketplace_negotiation_claim`, CHECK constraints, CASCADE semantics and operational indexes that Hibernate does not model
- preserves the anonymous market-stats observer fresh-install contract
- changes default Hibernate schema mode from `update` to `validate`
- adds a permanent clean-database workflow: empty PostgreSQL -> Flyway -> Hibernate validate -> `/actuator/health=UP` -> invariant checks
- adds a regression test proving a same-version `B` migration is ignored when an installation already has normal `V` migration history

### Evidence already obtained on this branch
- empty PostgreSQL 17 before startup
- Flyway validated all 36 migration resources
- only `B35 current schema baseline` executed (`SQL_BASELINE`)
- Hibernate ORM 7.4.1 validated the resulting schema successfully
- Spring Boot reached healthy state
- all 18 required application tables/invariants checked

The PR still needs the normal repository CI and permanent baseline workflow to pass on the final SHA before merge.
