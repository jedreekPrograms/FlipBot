## Description

Presentation-only visual system cleanup based on the latest UI feedback.

Instead of assigning vivid colors ad hoc, this replaces the previous screen-specific polish with one coherent semantic system:
- blue only for primary actions, focus, selection and informational progress
- green only for confirmed success/healthy states such as RUNNING, PURCHASED and negotiated savings
- amber only for waiting/attention states
- red only for destructive/failure states
- neutral metrics such as `Posiadane boty`, counters and metadata remain neutral
- Start actions are blue rather than green; green is reserved for state/outcome
- purchase effectiveness returns to a neutral KPI surface with only a slim success cue
- consistent light surfaces, borders, typography hierarchy, numeric rendering and form labels
- retains the improved negotiation-policy layout and tighter Price Matrix spacing
- keeps the UI flat/light with no glass, 3D or heavy shadows

Scope: only `frontend/src/styles/screen-polish-v2.css`. No component logic, API, backend, persistence, scheduler, quota or negotiation behavior changes.
