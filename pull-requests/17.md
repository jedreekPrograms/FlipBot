## Description

## Cel

Podłącza trwały `real_action_guard` z PR #16 do pierwszej realnej oferty (`FIRST_OFFER`).

Scheduler nadal pozostaje DRY RUN — ten PR nie włącza realnych ofert.

## Nowa kolejność pierwszej oferty

Po obowiązkowym final verify i pełnym przygotowaniu formularza:

1. `assertPreparedOfferReady()`
2. acquire persistent `FIRST_OFFER` guard
3. reserve daily quota
4. real submit
5. backend zapisuje `NEGOTIATING/currentStep=1`
6. po potwierdzonym sukcesie guard jest czyszczony best-effort
7. jeżeli błąd nastąpi po wejściu w real submit, guard zostaje w bazie i blokuje automatyczny dubel

## Zachowanie fail-closed

### Guard blocked
- prepared form jest zamykany
- quota NIE jest rezerwowana
- real submit NIE jest wykonywany
- run kończy się bez próby innego real offeru

### Błąd / brak quota przed submit
- guard jest zwalniany
- prepared form jest zamykany
- real submit NIE jest wykonywany

### Błąd po reserve + wejściu w submit
- quota NIE jest automatycznie zwalniana
- persistent guard NIE jest zwalniany
- kolejny run nie może bezwarunkowo powtórzyć tego samego realnego kliknięcia

### Potwierdzony sukces
- backend listing jest już `NEGOTIATING`
- guard jest zwalniany best-effort
- jeżeli cleanup guardu się nie uda, PR #16 potrafi później rozpoznać stale guard po stanie listingu
