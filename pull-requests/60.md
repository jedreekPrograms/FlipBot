## Description

### Problem
Fresh bot 6 logs from the S26 run show that the e-mail form appeared and the old code attempted submission only ~22 ms later. The run then stayed on `/member/login/email` for 60 seconds and failed authentication. The user also observed the credentials appear and then disappear without a real visible login transition.

### Changes
- wait for the React auth form to settle before filling controlled inputs
- verify both credential fields still contain the configured values after a stability window; re-fill if Vinted rewrites them
- resolve the submit control from the exact form containing the e-mail/password inputs instead of relying on one global hard-coded button name
- before every submit attempt, re-check that credentials are still stable
- attempt submission in a controlled order: form submit button click -> Enter on password -> `HTMLFormElement.requestSubmit()`
- require an observable post-submit transition; a completed Playwright click alone is no longer treated as success
- detect and report explicit authentication errors separately
- improve diagnostics without logging credential values
- human verification is now reported only from positive evidence (challenge iframe/text); ordinary DOM-read exceptions during navigation no longer count as a CAPTCHA
- add regression tests for accepted/rejected login submit labels

### Safety
- no credentials are logged
- authenticated session is saved only after a real authenticated signal
- no real marketplace offer/negotiation behavior is changed
- human-verification handling remains fail-safe when an actual challenge is visible
