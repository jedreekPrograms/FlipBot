## Description

## Problem
The observer now reaches and verifies exact Vinted model filters, but VINTED_MODEL scans still pass every catalog tile through the stricter negotiation matcher. Real runtime evidence showed 96 parsed iPad 10.9 listings being reduced to `matched=0`, so `Oferty dziś` / `Oferty ten tydzień` stayed at zero even though the catalog scan itself succeeded.

The same run also showed repeated category failures on later iPad targets: the leaf category was visibly selected, but `catalog[]` sometimes did not persist within the old 5s window.

## Fix
- restore the intended split between the two observer target modes:
  - `VINTED_MODEL`: after FilterService verifies the exact Vinted model and `brand_collection_ids[]` in the URL, count valid listing IDs from that verified catalog population directly
  - `SEARCH_QUERY`: keep the conservative per-listing matcher and accessory filtering unchanged
- do not loosen any real-negotiation target guards; the bypass exists only inside MarketStatsCollector
- preserve existing price-range filtering because min/max is still applied by FilterService before the scan
- make category persistence more tolerant: first allow normal auto-persist, then explicitly confirm the category panel if needed, and still fail closed unless `catalog[]` appears
- add tests protecting the VINTED_MODEL vs SEARCH_QUERY counting split

## Counting semantics
Backend observation recording already refreshes `lastSeenAt` for both new and previously-known listing IDs. Calendar planning uses the observation window (`firstSeenAt < window end` and `lastSeenAt >= window start`), so re-observed known listings now correctly contribute to `Oferty dziś` and `Oferty ten tydzień` instead of remaining zero.
