## Description

## Problem

The market-stats observer can keep traversing hundreds of old Vinted listings during an incomplete baseline even after it has already passed the only publication window used by the Cennik statistics. In the latest runtime log, iPhone 12 had already reached listings marked `REL|2 tyg.` / `REL|3 tyg.` and still continued toward the 600-listing cap.

That makes one popular model take many minutes and blocks the remaining models even though listings older than the previous full Monday-Sunday week cannot affect `Dzisiaj`, `Ten tydzień`, or `Poprzedni tydzień`.

## Changes

- compute the earliest relevant publication timestamp in `Europe/Warsaw` as the Monday starting the previous full week
- after each resolved catalog page, inspect the page tail in Vinted `newest_first` order
- stop the model once the 20 oldest consecutive resolved listings on that page are all older than the statistics window
- require all 20 timestamps to be known and old; any missing timestamp or still-relevant listing keeps traversal going
- preserve the existing known-listing boundary, no-growth boundary, 600-listing safety cap, and publication-resolution completeness guard
- make a statistics-window stop count as a valid completion boundary even when the page reaches the configured listing cap
- add an explicit runtime log explaining when and why the historical boundary stopped traversal

## Scope

Playwright market-stat catalog traversal only. No negotiation behavior, Vinted rate-limit handling, filters, backend statistics formulas, or mobile/frontend code is changed.

## Tests

- 20 consecutive historical tail listings confirm the stop boundary
- 19 historical listings do not
