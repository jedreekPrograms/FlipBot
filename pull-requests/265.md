## Description

## Root cause confirmed from captured Vinted HTML

The exact model row is the interactive control:

`data-testid="selectable-item-brand_collection-9977" role="button" tabindex="0"`

The nested checkbox is rendered inside `.u-no-pointer-events`:

`input[type=checkbox][name="brand_collection_ids[]"][value="9977"]`

So clicking/checking the nested input/label is not the intended primary interaction.

## Fix

- Click the canonical exact model row first.
- Treat the exact checkbox only as a state oracle.
- Require the checkbox to become checked before continuing.
- If row click does not toggle it, try keyboard activation (Enter, Space).
- Last resort: dispatch a native DOM click on the exact proven checkbox value.
- Never click a fuzzy/partial model.
- Final URL persistence check for the exact `brand_collection_ids[]` remains unchanged.

## Regression

Adds coverage for the exact checkbox selector bound to the proven collection id.
