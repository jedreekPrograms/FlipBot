## Description

## Problem
The anonymous market observer now starts correctly and reaches target filtering, but the latest runtime log shows Vinted's OneTrust preference-center overlay physically intercepting clicks on `catalog--catalog-filter--trigger` for the full 30-second Playwright click timeout. The blocker is specifically `.onetrust-pc-dark-filter` / `#onetrust-policy-text`, so the observer fails the first exact VINTED_MODEL target before any market scan can be recorded.

## Changes
- add a narrow browser-context OneTrust guard for every Playwright context
- handle both the normal banner accept control and OneTrust preference-center `accept-recommended` control
- match only exact known accept-all labels inside OneTrust DOM
- if the preference center itself is blocking the page and no accept-all control is available, use OneTrust's own save/close control instead of deleting/force-clicking DOM
- combine MutationObserver with a short bounded poll because OneTrust may attach handlers/open its preference center without a useful DOM mutation
- keep the existing anonymous-observer UI guard and exact model/category fail-closed checks unchanged
- add unit coverage for the exact OneTrust controls and absence of broad page-wide button clicking

## Safety
- no negotiation, real-action, quota or target-matching semantics change
- no arbitrary modal dismissal
- no DOM overlay removal or force-click through blockers
- normal logged-in bots remain compatible; their existing LoginService cookie handling is simply backed by the same narrowly scoped guard
