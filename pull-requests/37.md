## Baseline count storage

V22 adds `baseline_offer_count` to `market_model_scan_state` and backfills existing completed baselines from observations already marked `baseline=true`. New baselines store that count once when the first complete baseline scan finishes. Planning reads the stored value instead of running a baseline-count query for every model on every 15-second frontend refresh.

## Why

The latest observer log proves iPhone 12 was scanned with `minPrice=null` and `maxPrice=null` and matched 165 offers, but because it was the first baseline scan the UI showed `0 od startu pomiaru`. That value was technically correct for *new* offers but visually misleading.
