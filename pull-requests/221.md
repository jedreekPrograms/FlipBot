## Description

Peak-memory optimization on top of stable f9ac027.

- cap concurrently WORKING CATALOG_SCAN jobs at 3 by default
- keep worker count and RUNNING bot count unchanged
- defer excess catalog jobs back into the scheduler instead of blocking worker threads
- allow NEGOTIATION_CHECK / PRICE_PROBE to remain eligible while catalog capacity is full
- expose FLIPBOT_MAX_CONCURRENT_CATALOG_SCANS (1..100); set 10 to approximate the old behavior
- add scheduler tests proving excess catalogs defer and negotiations are not starved

No BrowserManager, session, negotiation decision, quota, backend or frontend code is changed.
