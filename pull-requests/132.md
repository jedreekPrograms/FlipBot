## Description

## Problem

A failed/interrupted Playwright `storageState` write could target the active `sessions/bot-X.json` directly. If the write was truncated, the active session could become a zero-byte file, as observed for bot 6.

## Fix

- write storageState to a sibling temporary file first
- reject empty or malformed storageState JSON
- require the expected `cookies` and `origins` arrays before installation
- replace the active session only after validation, preferring an atomic filesystem move
- keep the existing active session untouched when staging or validation fails
- treat zero-byte session files as unusable rather than valid stored sessions

## Regression coverage

- valid staged state replaces the active session
- empty staged state cannot truncate an existing active session
- malformed staged JSON cannot replace an existing active session
- zero-byte session files are not considered usable
- previous path-resolution and non-destructive recovery tests remain intact
