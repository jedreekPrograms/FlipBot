## Description

## Problem

Fresh/upgraded local databases fail during backend startup with:

`ERROR: column listing.last_terminal_watch_at does not exist`

The application runners execute in this order:

- BotAdditionalTargetSchemaInitializer: 100
- NegotiationStrategySchemaInitializer: 120
- NegotiationStrategySnapshotBackfillRunner: 130
- TerminalNegotiationWatchSchemaInitializer: 140
- HistoryAnalyticsSchemaInitializer: 200
- MarketStatsPublicationSchemaInitializer: 300

The strategy snapshot backfill uses JPA to load Listing rows. Hibernate selects every mapped Listing column, including `last_terminal_watch_at`, before the runner responsible for creating that column has executed.

That crashes the backend after Tomcat starts, and Playwright subsequently reports repeated connection failures because port 8081 is no longer available.

## Fix

Move NegotiationStrategySnapshotBackfillRunner to order 400 so every current additive local-schema initializer has completed before the first JPA Listing backfill query.

This changes startup ordering only. No negotiation state, prices, quotas, sessions, scheduler logic or marketplace behavior is changed.

## Regression test

Adds StartupRunnerOrderTest to enforce that the Listing JPA backfill remains ordered after all current schema initializers.
