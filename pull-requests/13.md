## Description

## Problem

W logach bota 3 nieudane próby ustawienia marki `Samsung` korelują z eventem nowej strony o pustym URL:

`[BROWSER] Closing unexpected browser page ... URL:`

Dotychczasowy popup guard zamykał każdą nową `Page` natychmiast, zanim jej URL zdążył się ustalić. Taka strona może być przejściowym elementem normalnego flow Vinted, więc jej natychmiastowe zamknięcie może zakłócać filtr marki.

Drugi problem był diagnostyczny: `TestApplication` uruchamia wyłącznie pierwszego RUNNING bota i nie korzysta z `WorkerManager`, więc nie pokazuje równoległej pracy slotów ani nie wysyła schedulerowej telemetry do `/runtime`.

## Zmiany

### Popup guard
- główna strona nadal nigdy nie jest zamykana
- nowa strona z pustym URL lub `about:blank` nie jest zamykana natychmiast
- dodatkowa strona Vinted nie jest zamykana
- tylko strona z jednoznacznie zewnętrznym URL jest zamykana
- błąd klasyfikacji popupu jest defensywny: strona zostaje otwarta do zamknięcia całego krótkotrwałego BrowserContextu
- istniejące stare dodatkowe karty są nadal sprzątane przy tworzeniu BotContext

### TestApplication
Dodany wyraźny warning, że:
- jest to legacy/manual SINGLE-BOT runner
- wykonuje tylko `runningBots.getFirst()`
- nie używa worker slotów
- nie zasila scheduler runtime telemetry
- do testu równoległości i `/runtime` trzeba uruchomić `FlipBotPlaywrightApplication`

## Safety

PR nie zmienia:
- `FilterActions` (w tym poprawionego Java text blocka)
- negocjacji
- quota
- target matchingu
- schedulera ani liczby slotów
- real-offer flags
- frontend/backend runtime API

Realne oferty i next steps pozostają wyłączone zgodnie z istniejącą konfiguracją.

## Test po merge

1. Do testu pojedynczego filtra można nadal używać `TestApplication` i obserwować, czy znikają wpisy `Closing unexpected browser page ... URL:` przy próbie marki.
2. Do testu wielobotowego uruchomić `pl.flipbot.playwright.FlipBotPlaywrightApplication` przy co najmniej dwóch botach w stanie RUNNING.
3. W logach powinny pojawić się osobne `[SLOT n] Claimed ...` dla różnych botów, a `/runtime` powinien zacząć pokazywać `QUEUED/WORKING`, slot i czasy jobów.
