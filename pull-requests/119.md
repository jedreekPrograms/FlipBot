## Description

Fixes the discovery lifecycle gap where a listing that had ever left DISCOVERED was ignored forever by later fresh scans just because the same marketplace ID already existed for that bot.

Behavior:
- fresh catalog scans still run at the normal cadence
- an existing pre-negotiation listing may be requalified only if it reappears in the current fresh scan
- each listing can enter this daily requalification path at most once per Europe/Warsaw day
- retryable transient statuses: UNAVAILABLE, SKIPPED_OFFER_TOO_LOW, SKIPPED_OUTSIDE_PRICE_RANGE, SKIPPED_CANNOT_NEGOTIATE, SKIPPED_TARGET_MISMATCH
- never requalifies PURCHASED, FINISHED, EXPIRED, SKIPPED_BY_USER, SKIPPED_ALREADY_NEGOTIATED or any listing with conversation/started-step state
- a confirmed FIRST_OFFER is a hard permanent blocker for rediscovery
- refreshed title/url/observed price are persisted before the listing is returned for normal current target/availability/ownership/quota/capacity verification
- existing DISCOVERED rows are backfilled as seen today so they are not recycled twice on deployment day

Adds V35 for last_fresh_discovery_at and focused regression tests.
