## Description

## Cel

Dodaje ostatnią warstwę bezpieczeństwa przed pierwszym kontrolowanym real-action testem: `PREFLIGHT ONLY` + walidator gotowości bota.

## Nowy env

`FLIPBOT_REAL_ACTION_PREFLIGHT_ONLY=true`

Przy tym ustawieniu można podać dokładnie te same env-y co do realnego testu, ale system NIGDY nie przekaże `realOffersEnabled=true` ani `realNextStepsEnabled=true` do procesorów.

## Preflight sprawdza

- poprawny bot id i obecność konfiguracji
- marketplace `VINTED`
- category path
- target mode (`SEARCH_QUERY` albo `VINTED_MODEL`) i wymagane pola targetu
- min/max price i ich relację
- dodatni daily negotiation budget
- negotiation steps: brak nulli, sekwencja od 1, unikalność, dodatnie offerPrice
- dla controlled FIRST_OFFER testu step #1 musi mieć niepustą wiadomość
- dla FIRST_OFFER backend musi obecnie pozwalać na co najmniej jedną nową negocjację
- dla NEXT_STEP loguje liczbę aktywnych `NEGOTIATING` i wymaga co najmniej dwóch skonfigurowanych stepów

## Zachowanie

Preflight loguje jednoznacznie:
- `[REAL ACTION PREFLIGHT] READY ...`
- albo `[REAL ACTION PREFLIGHT] BLOCKED ... Failures: ...`

Jeżeli jest `BLOCKED`, real actions są automatycznie downgraded do DRY RUN.

Jeżeli jest `READY`, ale `FLIPBOT_REAL_ACTION_PREFLIGHT_ONLY=true`, nadal pozostaje DRY RUN.

## Safety

Nie zmienia:
- persistent FIRST_OFFER / NEXT_STEP guardów
- quota semantics
- target matchingu
- negocjacyjnych decyzji i timerów
- `FilterActions`
- popup guarda
- schedulera queue/priority
- Buy now / ACTION_REQUIRED
