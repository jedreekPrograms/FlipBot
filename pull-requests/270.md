## Description

## Behavior

`Wyświetl sesję` now becomes a true LIVE mode instead of a passive/paused preview.

- Generic workers stop claiming that bot, so there is still exactly one session owner.
- A dedicated headed owner keeps Chromium visible and claims the bot's **normal scheduler jobs** (`CATALOG_SCAN`, `NEGOTIATION_CHECK`, etc.) on the same schedule.
- Between jobs the visible bot session stays open for inspection/manual recovery.
- Before each normal job the healthy visible state is checkpointed, the idle context closes, and the normal production executor runs in the same headed Chromium runtime.
- After the job, the visible idle session is reopened from the newest validated session state.

## CAPTCHA / manual recovery

- If CAPTCHA/auth/session trouble is observed, the live window stays available.
- After the user solves it and a strong authenticated Vinted signal appears, FlipBot writes the refreshed storage state through the existing staged validation + last-known-good backup path.
- A new `SESSION_RECOVERED` runtime event clears the persisted session-block episode/cooldown.
- The in-memory scheduler cooldown is also released so due work can resume immediately after verified recovery.
- A normal live job still uses the existing HumanVerificationHandler and normal session persistence behavior.

## Safety

- No concurrent normal worker + preview browser for the same bot.
- Existing in-flight generic job is never interrupted; live ownership begins after it finishes.
- Session writes require strong authenticated evidence and still pass SessionManager validation.
- Hiding preview waits for the live owner to fully exit before generic workers can resume.

## UI

Runtime now labels the session as `LIVE · bot normalnie pracuje w widocznym Chromium`, and telemetry worker slot `0` renders as `LIVE`.

## Tests

Adds scheduler tests for live-preview claiming and immediate resume after verified session recovery, plus backend coverage that `SESSION_RECOVERED` clears persisted cooldown state.
