## Description

## Goal
Treat configured negotiation steps as a reusable relative ladder instead of absolute prices only.

Example base configuration:
- step 1: offer 900, accept counteroffer up to 950
- step 2: offer 1000, accept up to 1050
- step 3: offer 1050, accept up to 1100
- global automatic negotiation cap: 1500

For a 2000 PLN listing, if the configured 900 PLN first offer is below Vinted's minimum, adaptive mode calculates the minimum from the listing price, rounds strictly upward to the next 50 PLN bucket (1200 -> 1250), and uses that as the effective first offer. Later steps preserve the configured step-to-step ratios using the actually sent price and round upward to 10 PLN.

## Changes
- add `AdaptiveNegotiationPricingService`
  - first adaptive offer: strict next-50 rounding
  - later offers: configured percentage progression, ceil to 10 PLN
  - dynamic seller-counter acceptance thresholds scale with the effective current offer
  - `maxAutomaticOffer` becomes the global automatic negotiation ceiling in adaptive mode
- add `AdaptiveFirstOfferExecutor`
  - keeps the configured first offer as the first choice
  - if it is too low, retries adaptively in 50 PLN increments up to the global cap
  - preserves existing guard/quota/fail-closed submission path
- rejection decisions now send a scaled next step
- pending/read/seller-message timer continuation now sends a scaled next step
- seller counteroffers are compared against the scaled acceptance threshold
- if a calculated next offer would exceed the global cap, automatic escalation stops
- configured step messages and step numbers are preserved unchanged
- frontend copy now describes the setting as an adaptive negotiation ladder and the cap as a global negotiation maximum
- adaptive mode requires strictly increasing configured offer prices so step-to-step percentages are well-defined; static mode remains backward compatible
- Flyway V23 requeues legacy `SKIPPED_OFFER_TOO_LOW` listings once so offers skipped by the old absolute-price behavior get another chance under the new policy; static bots will safely reclassify them if still too low

## Safety
- no action guard, quota, idempotency, preflight, daily-budget, or production-mode protections are removed
- static pricing mode continues to use configured absolute prices
- no new configuration columns are required; the existing strategy fields are reused
