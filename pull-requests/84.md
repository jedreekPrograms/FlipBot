## Description

## Stage 4: fail-closed price-probe crash recovery

A browser probe can successfully/ambiguously attempt a real marketplace message and then lose the callback to the backend. Previously that row stayed `CLAIMED` indefinitely while the source negotiation stayed active.

### Fix
- after 30 minutes, unreported `CLAIMED` probes transition to `UNKNOWN`, never `CANCELLED`
- `UNKNOWN` continues to reserve a probe slot and the unique bot/listing row remains, so recovery can never authorize an automatic resend
- recovery uses one conditional JPQL UPDATE (`WHERE status=CLAIMED AND claimed_at<=cutoff`) rather than load+save, preventing a stale cleanup entity from overwriting an already-confirmed `SENT`
- fresh in-flight claims and already-final states are not touched

### Tests
- service test verifies the exact 30-minute cutoff and fail-closed recovery reason
- real Spring/PostgreSQL repository test verifies stale CLAIMED -> UNKNOWN, fresh CLAIMED unchanged, SENT unchanged, and all three still reserve slots

No schema migration is required.
