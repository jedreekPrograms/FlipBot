## Description

## Problem

The Cennik collector could still walk deep into months-old Vinted listings after #181, and legacy models could show `0 / 0 / 0` as if their calendar statistics were complete.

Two state mismatches caused this:

1. The historical stop boundary only saw publication timestamps resolved in the current Playwright pass. Listings whose immutable `published_at` was already stored in PostgreSQL were intentionally not reopened, but their stored timestamp was also absent from the in-memory boundary map. A mixed page therefore could not prove the 20-old-listing boundary even when the database already contained the evidence.
2. `last_scan_complete=true` predates publication-time backfill. Legacy scan states could therefore mark today/current-week/previous-week windows complete even when their observations still had no real Vinted `published_at` values.

## Changes

### Persisted publication timestamps are reused end-to-end
- maps `published_at` on `MarketListingObservation` and exposes stored publication timestamps through `GET /api/market-stats/models/{modelId}/publication-times`;
- seeds those immutable timestamps into `MarketStatsObservationContext` before a scan;
- `resolvedFor(...)` now exposes persisted + freshly resolved timestamps to the existing #181 historical-boundary check;
- detail resolution still opens only new/missing listings; persisted timestamps are not rewritten or re-fetched;
- publication POSTs now contain only timestamps freshly resolved in the current pass.

### Publication-window completeness has its own state
- adds nullable `market_model_scan_state.publication_window_complete_at` (V37 plus the runtime compatibility initializer used by the local Flyway-disabled setup);
- legacy rows deliberately remain NULL, so an old `last_scan_complete=true` cannot claim publication-window coverage;
- `/full-catalog-scan-required` now forces a complete retry when this marker is absent;
- after a forced scan completes with publication timestamps available for every accepted listing, Playwright confirms the window through `/publication-window-complete`;
- the backend refuses to set the marker unless the model has a complete baseline and the latest scan is complete.

### Calendar UI completeness is no longer inferred from legacy scan state
- today/current-week completeness requires established publication coverage, a complete latest scan, and a successful scan from today;
- previous-full-week availability requires established publication coverage and a successful scan in the current week;
- this prevents stale/legacy Samsung rows from presenting `0 / 0 / 0` as trustworthy while their publication backfill is still pending.

## Scope / safety

- no Vinted rate-limit bypass or traffic evasion;
- exact Vinted model filtering and existing fail-closed behavior are unchanged;
- previously stored immutable publication timestamps are reused specifically to reduce repeated item-detail traffic;
- interrupted scans still persist partial observations/freshly resolved timestamps and remain incomplete;
- no frontend contract changes are required.

## Tests

Added/updated unit coverage for:
- legacy `last_scan_complete=true` still requiring a full scan when publication-window coverage is missing;
- complete publication-window state allowing the known-listing boundary again;
- backend retrieval of persisted publication timestamps;
- publication-window marker refusing incomplete scans;
- Playwright reusing persisted timestamps for historical-boundary evidence without re-posting them;
- new/missing listings still requiring detail resolution and full-refresh semantics remaining available for explicit tests.
