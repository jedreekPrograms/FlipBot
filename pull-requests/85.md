## Stage 5: encrypted Playwright session storage

Playwright storage-state files contain authenticated marketplace cookies/localStorage and were previously persisted as plaintext `sessions/bot-<id>.json` files. This PR makes persistent session material encrypted and upgrade-safe without changing offer/negotiation behavior.

### Security and runtime behavior
- stores persistent session state as AES-256-GCM `bot-<id>.state.enc`
- binds ciphertext to the owning bot ID with AES-GCM AAD so session files cannot be swapped between bots
- never writes plaintext Playwright storage state to a temporary disk file; decrypted JSON is passed to Playwright via `setStorageState(String)` in memory
- supports dedicated `FLIPBOT_SESSION_ENCRYPTION_KEY`, falling back to `FLIPBOT_ENCRYPTION_KEY`
- uses owner-only POSIX permissions where supported (`0700` directory, `0600` files)
- legacy plaintext `.json` migrates only after encrypted state is written, read back and authenticated
- an existing encrypted file is never overwritten unless the currently configured key first authenticates it
- if encrypted state cannot be opened because the worker has a missing/wrong key, the file is left untouched and the browser job starts clean so normal login can continue
- if legacy plaintext cannot yet migrate, it can still be restored in memory for that run instead of breaking the upgrade
- removes session files only for bot IDs that no longer exist; STOPPED bots keep their session

### Tests
- ciphertext-only at rest + round trip
- owner-only permissions where supported
- legacy plaintext migration
- wrong-key read fails closed
- wrong key cannot overwrite prior valid ciphertext
- ciphertext is bound to bot ID
- orphan cleanup preserves existing bots
- legacy upgrade fallback remains usable
- corrupted/unavailable encrypted state falls back to clean context without deleting the file
- Bot API all-bots parsing used by cleanup

No database schema or real-action logic is changed.
