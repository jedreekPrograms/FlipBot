## Description

## Required behavior

When adaptive negotiation reaches `maxAutomaticOffer`, Flipbot must **not** stop the configured ladder. It must continue through every remaining configured step using the same capped price, while preserving that step's own message and response policy.

Example:

- configured prices: 1000 / 1100 / 1200 / 1300 / 1400
- `maxAutomaticOffer = 1200`
- effective prices: 1000 / 1100 / 1200 / 1200 / 1200
- messages: step 1 / step 2 / step 3 / step 4 / step 5 respectively

## Fix

- Adaptive pricing now clamps a calculated next price to the global cap instead of returning no next step.
- Once the current real offer already equals the cap, later configured steps stay on that exact price.
- Same-price next steps are permitted only for this adaptive-cap plateau. Lower prices and same-price steps below the cap still fail closed.
- Configured step number, message and response policy are preserved.
- A configuration cap lowered below an already-sent offer still fails closed; Flipbot never lowers an active offer automatically.
- The bot form now explains the plateau behavior explicitly.

## Regression coverage

- calculated next offer above cap -> capped next step is still generated;
- step 3 at 1200 -> step 4 at 1200 with message 4;
- step 4 at 1200 -> step 5 at 1200 with message 5;
- decision service sends the capped next step instead of marking the negotiation rejected;
- equal-price offers are accepted only when current/next price both equal the active adaptive cap.
