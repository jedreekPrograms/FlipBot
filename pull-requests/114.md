## Description

## Problem
Vinted currently emits seller message timestamps such as `1.09.2026, 12:27:39`, while `ConversationActivityDetector` required `dd.MM.yyyy`. The detector therefore saw seller messages but persisted their activity time as null. For a PENDING conversation without a read indicator this incorrectly fell back to the 48-hour no-engagement timeout instead of the intended seller-message + 3-hour policy.

## Fix
- accept one- or two-digit day/month in Vinted timestamps via `d.M.yyyy, HH:mm:ss`
- keep invalid/unrecognized timestamps fail-closed as null
- add regression tests for current Vinted format, zero-padded format, single-digit day/month, and invalid input

No schema/data changes.
