## Description

## What
- install a headless-only BrowserContext route guard
- abort only `image` and `media` subresources while the top-level page is the real `https://*.vinted.pl/catalog` surface
- never block document/script/style/XHR/fetch traffic
- keep common Cloudflare/hCaptcha/reCAPTCHA challenge asset hosts available
- fail open if route classification is uncertain
- add pure policy regression tests for catalog scope, functional resource types, lookalike hosts and challenge exceptions

## Why
Each active Chromium tree is currently heavy. FlipBot's catalog scanner reads image URLs from DOM `src` attributes and does not inspect decoded image pixels, so downloading/decoding catalog thumbnails is avoidable memory/GPU/network work. The optimization is intentionally restricted to headless catalog browsing and does not affect login, inbox, item-detail pages, or saved sessions.
