## Description

## Problem
Editing only the global negotiation cap could still fail with:

`Bot has active negotiations... category.`

The category hierarchy is stored as an `@ElementCollection List<String>`, but until now it had no `@OrderColumn`. PostgreSQL/JPA therefore did not guarantee that the hierarchy elements would be loaded in the same order on every request. A bot that semantically still had the same category could be seen as changed by the active-negotiation lock because `BotService` compares the two lists exactly.

This also matters outside editing: Playwright navigates category hierarchy in list order, so category path order should be persisted explicitly.

## Fix
- add `@OrderColumn(name = "path_index")` to `BotConfiguration.categoryPath`
- add Flyway `V24__persist_bot_category_path_order.sql`
  - reconstructs existing category order from canonical `dictionary_category.path`
  - stores zero-based `path_index`
  - makes it NOT NULL
  - adds a unique `(configuration_id, path_index)` index
- add a mapping regression test so category-path ordering cannot be accidentally removed later

## Expected result
After pulling and restarting the backend so V24 runs, changing only the global negotiation cap while active negotiations exist no longer produces a false `category` change. The stored hierarchy order is also deterministic for Playwright category navigation.
