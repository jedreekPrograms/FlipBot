## Description

## Why
Runtime logs exposed multiple reasons historical opportunities were being starved:

1. Bot 3 had 145 price-eligible DISCOVERED listings and 56 S25 target matches, but backend returned `may start 0 new negotiations`. Capacity was reserving every theoretical future step of every active conversation, so a few active negotiations could consume the entire theoretical budget even though those future actions had not happened.
2. Bot 4 found a clear S11 Ultra candidate by URL, but mandatory final item-page verification failed because the expected Vinted h1 layout did not appear in time.
3. Historical target mismatches stayed DISCOVERED forever, repeatedly polluting the backlog.
4. The runtime log also exposed `Galaxy S25 Edge` being accepted as plain `Galaxy S25`.

## Changes
- negotiation capacity now reflects actual remaining daily action quota instead of pre-reserving hypothetical future steps
- configured `dailyNegotiationBudget` is the actual per-bot daily limit for real price actions (first offers + next steps), capped at 25
- future steps consume quota only when they are actually about to be sent
- frontend copy explains those budget semantics
- final item-page title verification supports the normal Vinted selector plus `main h1` / `h1` fallbacks and gives useful diagnostics on failure
- known unavailable listing pages are classified separately and persisted as `UNAVAILABLE`
- final verification can inspect up to 20 candidates until it finds enough verified candidates for the current run, preventing stale historical entries from starving valid listings behind them
- clear catalog/URL/detail target mismatches are persisted as `SKIPPED_TARGET_MISMATCH` so they stop polluting the DISCOVERED backlog
- transient verification errors remain DISCOVERED and are retried later while processing continues with later candidates
- target changes requeue prior `SKIPPED_TARGET_MISMATCH` listings; Vinted account identity changes requeue `SKIPPED_CANNOT_NEGOTIATE`
- plain S25 now explicitly rejects the `Edge` variant, with a regression test
- adds Flyway V27 for the new target-mismatch status

## Safety
- real-action preflight remains enabled
- persistent FIRST_OFFER/NEXT_STEP guard remains enabled
- quota is still reserved immediately before a real submit
- ambiguous post-submit failures remain fail-closed
- per-run real-offer limit remains enforced (default 3)
- exhausted actual daily quota still blocks new offers
- transient live-verification problems do not permanently discard a listing

## Tests
- capacity uses actual remaining quota without future-step reservations
- exhausted quota returns zero capacity
- missing negotiation steps fail closed
- configured bot daily budget is reflected in quota limit/remaining values
- S25 Edge is rejected as a different variant while normal S25/SM product-code cases stay valid
