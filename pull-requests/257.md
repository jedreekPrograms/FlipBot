## Description

Session audit fix prompted by repeated random logouts (including bots 10 and 13).

The login fast-path could previously treat `trusted Vinted page + no visible login controls` as authentication evidence. A partially rendered or logged-out page can satisfy that condition. ScheduledBotRunExecutor then immediately persisted a pre-job checkpoint, creating a path that could overwrite a previously good bot-X.json with unauthenticated storage state.

This change:
- removes control-absence as authentication evidence for restored sessions;
- removes the same weak fallback after interactive login/CAPTCHA;
- requires a visible conversations button or inbox link before login is considered authenticated;
- adds a second VintedSessionPersistenceGuard check immediately before the scheduled pre-job checkpoint;
- keeps ambiguous pages fail-closed and leaves the previously stored session untouched;
- adds focused unit coverage that control absence is not authentication evidence.

No credentials, scheduler cadence, negotiation pricing, quota, catalog matching, or session-file deletion behavior changes.
