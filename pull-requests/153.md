## Description

## Co zmienia

- po pierwszym wykryciu CAPTCHA nadal natychmiast otwiera pojedyncze widoczne okno dla tej samej sesji `bot-X.json`
- po upływie limitu lub zamknięciu okna zapisuje trwały stan `CAPTCHA_REQUIRED` i usuwa automatyczne joby tego bota z kolejki
- dodaje w Runtime przycisk `Zaakceptuj CAPTCHA`, który dopiero na żądanie otwiera nowe widoczne okno
- po poprawnej ręcznej weryfikacji czyści blokadę i natychmiast wznawia normalny harmonogram
- pozostawia inne boty aktywne i serializuje widoczne okna CAPTCHA

## Bezpieczeństwo sesji

Recovery korzysta z istniejącego `sessions/bot-X.json`; nie tworzy drugiej logicznej sesji konta. Okno headless jest zamykane przed uruchomieniem headed, a zapis nadal przechodzi przez atomowy mechanizm pliku tymczasowego.

## Weryfikacja

- `frontend: npm run build`
- `frontend: npm run lint`
- testy backendu dla trwałego stanu i idempotentnego żądania recovery
- testy schedulera dla pauzy bez retry i wznowienia tylko po żądaniu
- pełna kompilacja Java i pozostałe testy przez GitHub Actions (JDK 21)
