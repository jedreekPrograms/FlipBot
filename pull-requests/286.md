## Description

## Root cause
The market Observer could be starved for hours even while normal bots were healthy:
- Observer deferred any new browser batch at >=82% RAM.
- Normal worker scheduling treats 80-86% as only elevated pressure and may continue with multiple workers.
- LIVE session preview owns an additional persistent headed Chromium but was not counted against generic worker browser capacity.
- Price Matrix also treated a complete scan as unusable after a fixed 120 minutes, which is too short for large model sets.

## Fixes
- raise Observer memory deferral threshold from 82% to 90%, while retaining the 2 GiB absolute free-memory guard
- retry temporary memory deferral every 5 minutes instead of 10
- count active LIVE headed previews against generic worker-slot capacity
- scale Price Matrix freshness window with target count (120-360 min)
- separate complete coverage from freshness: a complete scan from today remains a valid count and the UI shows its exact "stan na" timestamp
- distinguish no full scan today from missing baseline
- expose currentWindowFresh and lastSuccessfulScanAt in planning response
- health now counts stale models individually instead of declaring OK because one model was scanned recently
- health freshness also scales with model count
- show stale-model count plus newest/oldest successful model scan in Observer UI

## Safety
No offer submission, negotiation timing, hard 25/day quota, market filtering, tracking generations, or session persistence semantics are changed.
