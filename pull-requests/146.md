## Description

## What changed
- create a fresh Playwright browser runtime for each claimed scheduled job
- close the whole browser runtime immediately after the job finishes, before the worker slot waits in the scheduler again
- keep bot sessions persistent through the existing per-bot `sessions/bot-<id>.json` storage state

## Why
Worker slots were intentionally long-lived and kept their Chromium runtime alive between jobs. With multiple bots this left several headless Chrome processes sitting idle in RAM for minutes at a time.

The bot session lifecycle is independent from the Chromium process: `BotContext` restores the bot-specific stored session on each run and `ScheduledBotRunExecutor` saves the updated session before closing the context. Closing the browser therefore does not reset the bot's login/session.

## Expected runtime behavior
`claim job -> launch browser -> restore bot session -> run -> save bot session -> close context -> close browser -> wait`

No scheduler/cooldown/negotiation timing behavior is changed.
