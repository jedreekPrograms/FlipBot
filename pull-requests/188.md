## Description

## Problem
Additional targets are deactivated rather than deleted so historical conversations keep their original strategy. Because `listing` is unique by `(bot_id, listing_id)`, old pre-negotiation rows remain owned by the disabled target. When the user follows the UI guidance and adds that product again as a new target, fresh scans see those rows as cross-product overlaps and can never claim them.

## Changes
- allow a fresh scan to reuse the existing backend listing row when its previous owner is an inactive additional target
- permit reassignment only for pre-negotiation/retryable states (`DISCOVERED`, selected safe `SKIPPED_*`, `UNAVAILABLE`)
- require step 0, no conversation, and no seller-response wait state
- preserve the row id and rebind its `additionalTarget` to the currently scanned product (or MAIN)
- keep active-target ownership and all negotiation/terminal states fail-closed
- block reassignment after any FIRST_OFFER audit, including `AMBIGUOUS`
- also make normal daily rediscovery fail-closed on ambiguous FIRST_OFFER audits
- add service-level regression coverage for safe reclamation and protected overlaps

## Safety
No listing with a started conversation, active negotiation, deliberate terminal state, or evidence that a real first offer may have been submitted can move between products.
