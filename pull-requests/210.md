## Description

Fourth resource-audit step. Keep the existing single-thread FIFO telemetry ordering while removing its unbounded pending-work queue.

Changes:
- replace Executors.newSingleThreadExecutor() with an explicit single-thread ThreadPoolExecutor
- hard-bound pending telemetry work to 256 events
- preserve FIFO execution and daemon telemetry thread
- use AbortPolicy so saturation is explicit instead of silently reordering via caller-runs behavior
- asynchronous telemetry logs and drops only after the hard limit is reached
- synchronous scheduler-significant telemetry fails explicitly on saturation, allowing the existing conservative session-block fallback to apply
- add a regression test proving the queue cannot grow beyond the configured bound

No browser lifecycle, scheduler cadence, negotiation logic, market-stats, frontend or backend runtime-state semantics are changed.
