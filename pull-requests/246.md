## Description

Full-audit regression fix.

Two previously merged scheduler protections had regressed from stable:
- catalog work had returned to DelayQueue + synthetic 1s retry polling when catalog capacity was full;
- ordinary failures had returned to a fixed retry delay instead of per-job adaptive backoff.

This restores the post-#225/#227 scheduler behavior while preserving current runtime features around it:
- due catalog work waits for real released capacity instead of occupying workers / retrying every second;
- negotiation work remains eligible while catalog capacity is full;
- catalog slot release wakes scheduler waiters immediately;
- catalog and negotiation failure counters stay independent;
- adaptive retry remains 2/5/10/15m for catalog and 1/2/5/10m for negotiation, with success resetting only that job type;
- current 120s negotiation cadence is retained;
- current BrowserCapacityController, persisted session-block cooldowns, preview handling and browser lifecycle remain intact.

Restored regression tests cover immediate capacity handoff and adaptive failure reporting/reset semantics.
