## Description

### Why
Fresh headed observer logs show OneTrust physically covering Vinted catalog controls and intercepting pointer events. The normal login flow accepts that banner, but the anonymous market observer intentionally skips LoginService, so the banner can survive across observer navigation/reset and make category/model scans fail.

The same run also showed a Vinted DOM variant for `Galaxy A56`: the exact option was visibly rendered, but the selectable `brand_collection` node exposed no readable label to the strict matcher, so the observer failed closed before it could reach `Pokaż wyniki`.

### Changes
- add an anonymous-observer-only init script that automatically accepts the standard OneTrust `accept all` consent whenever it appears, including after page navigation/reset
- accept only the known OneTrust control / exact `Zgoda na wszystkie`, `Akceptuj wszystkie`, `Accept all`, `Allow all` labels
- normalize unlabeled Vinted model selectable nodes by exposing text only from the smallest DOM ancestor that contains exactly one `brand_collection` id
- never invent or choose a collection id; existing strict exact-label verification remains authoritative
- deliberately refuse whole-filter-panel text such as `Pokaż wyniki`/`Clear filters` as model evidence
- keep existing exact model confirmation logic unchanged: the `Pokaż wyniki` click still has 3 UI attempts plus exact proven-ID recovery and must verify the exact `brand_collection_ids[]` in the final URL
- add regression coverage for the observer UI guard

### Safety
- normal negotiation bots are unchanged
- target/model strictness is unchanged
- quota, RealActionGuard and offer/next-step behavior are unchanged
- observer remains anonymous and read-only
