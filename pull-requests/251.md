## Description

Full-audit integration fix after restoring the adaptive scheduler.

A local BrowserCapacityUnavailable deferral used `completeRun(... reportQueued=true)`. In the adaptive scheduler, a reported successful completion resets that job type's failure counter. Therefore a job that had already failed could lose its escalating backoff merely because the next due attempt waited for local RAM/CPU capacity without running.

This adds a dedicated capacity-deferral path that:
- releases the scheduler claim;
- retries shortly (current 5s behavior);
- preserves existing per-job failure counters;
- does not create a failure or a success event;
- leaves session and marketplace state untouched.

Regression coverage proves a catalog failure sequence remains 2m -> capacity wait -> 5m on the next real failure.
