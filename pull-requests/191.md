## Description

## Problem
After safe disabled-target reclamation was added, every cross-product listing overlap attempted a separate `REQUIRES_NEW` locked reassignment transaction. Most overlaps are obviously non-reassignable from the already loaded row (for example another active product owns it, or it is already negotiating), so heavily overlapping filters could create many unnecessary lock transactions per scan.

## Changes
- perform the existing immutable safety pre-check against the already loaded `Listing`
- skip the locked reassignment transaction immediately for protected overlaps
- still run the locked method for candidates that may actually belong to an inactive pre-negotiation target
- keep the locked method's duplicate safety checks and FIRST_OFFER audit checks unchanged
- add regressions proving active-product and negotiating overlaps never invoke the locked reassignment path

## Safety
This is an optimization only. A listing is never reassigned based solely on the cheap pre-check; candidates that pass it still enter the existing locked/fail-closed reassignment transaction before mutation.
