## Description

## Problem
Fresh local runtime logs from the current mobile-monitor branch confirm that the market observer is now correctly anonymous, but OneTrust's preference-center overlay still blocks catalog filter clicks. Playwright resolves the category trigger, then `.onetrust-pc-dark-filter` / `#onetrust-policy-text` intercept pointer events until the category scan times out. Normal authenticated bot workers continue to select the same Vinted filters successfully.

## Changes
- restore the previously proven narrow `OneTrustConsentGuard` from PR #161
- install it for every new BrowserContext alongside the existing informational-dialog guard
- handle OneTrust accept-all / accept-recommended controls and preference-center save/close controls
- keep the behavior narrow: no arbitrary DOM deletion and no force-click through overlays
- add focused regression coverage

## Scope
No changes to bot session persistence, login/CAPTCHA semantics, negotiation logic, market counting semantics, model verification, or backend data. This only removes the blocking OneTrust consent UI using OneTrust's own controls.
