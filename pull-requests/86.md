## Stage 6: full-stack startup smoke

This adds a permanent integration gate for the exact local runtime shape used after `git pull`, without touching marketplace actions.

### What the smoke does
- starts PostgreSQL 17 from an empty database
- builds and starts the real Spring Boot jar with normal Flyway + Hibernate validate ownership
- waits for `/actuator/health = UP`
- verifies the scheduler running-bots endpoint and `/api/bots` both return valid JSON arrays
- builds and starts the real `FlipBotPlaywrightApplication` JVM against that backend
- disables market-stats collection for this smoke so no marketplace/network action is attempted
- speeds only the scheduler sync interval to 1 second
- requires the Playwright scheduler to complete an actual backend reconciliation
- requires session-retention reconciliation to communicate with `/api/bots` successfully
- fails if either process exits unexpectedly
- sends SIGTERM to the Playwright runtime and requires `Scheduler runtime stopped.` before accepting the run
- always prints runtime logs and cleans up child processes

This is intentionally a cross-module startup test rather than another unit test. It catches API/config/bootstrap mismatches that can otherwise pass backend and Playwright test suites independently.
