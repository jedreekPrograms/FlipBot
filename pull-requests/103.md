## Description

Integrates the existing defensive fingerprint laboratory with FlipBot's regular BrowserManager pipeline while preserving all current safety boundaries.

Key points:
- normal runtime behavior is unchanged unless `FLIPBOT_FINGERPRINT_RUNTIME_INTEGRATION=true`
- integration additionally requires the existing `FLIPBOT_FINGERPRINT_LAB=true`
- integration additionally requires `FLIPBOT_FINGERPRINT_LAB_URL` to pass the existing loopback / `*.localhost` / `*.test` allowlist
- invalid or production targets fail closed before the BrowserContext is created
- active lab-integrated contexts receive the existing synthetic fingerprint profile at context-init time
- active lab-integrated contexts reuse the existing HTTP(S)/WebSocket network boundary and Service Worker blocking
- Vinted and arbitrary production hosts remain rejected even if both feature flags are enabled
- no changes to MarketplaceNavigator, login, scanning, negotiation, workers, session behavior, or the existing allowlist
- adds regression tests specifically proving Vinted remains rejected
