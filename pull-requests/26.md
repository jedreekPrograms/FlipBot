## Description

## What changed
- add Flyway V18 `real_action_audit` table keyed by the exact persistent-guard `request_id`
- persist bot/listing/marketplace/conversation snapshot, action type, step, price, outcome, message status, failure reason and timestamps
- expose idempotent audit record API plus per-bot audit history endpoint
- require a matching persistent action guard before a new audit record can be created
- confirmed records are validated against backend listing state and use the backend-confirmed current price
- next-step real submit records `CONFIRMED` before guard cleanup and records `AMBIGUOUS` on post-submit failure
- confirmed first offers persist audit before guard cleanup
- unresolved stale guards backfill `AMBIGUOUS`; listing-confirmed stale guards backfill/reconcile `CONFIRMED` before cleanup

## Fail-closed behavior
- audit persistence never moves quota reservation earlier
- no Vinted click/navigation/target logic changed
- if confirmed first-offer audit persistence fails, its guard is intentionally retained for later reconciliation
- if confirmed next-step audit persistence fails, the guard remains because cleanup happens only after audit persistence
- ambiguous audit price may be null when the exact old attempted price cannot be proven; the audit never guesses from a later edited configuration
- message status starts as `UNKNOWN` unless separately proven; the audit never claims a message was sent without confirmation

## Existing behavior preserved
- dry runs are not written to the real-action audit table
- persistent guards and quota semantics remain fail-closed
- max real actions per job and controlled real-action flags are unchanged
