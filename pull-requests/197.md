## Description

## Problem
Additional products already persist their own category path and Playwright applies that category per product, but a direct API request could still combine a known dictionary model with a different category or target mode. The frontend now filters obvious mismatches, but the server should fail closed on known dictionary contradictions too.

## Fix
- add a reusable dictionary target compatibility guard
- resolve a known dictionary target by brand + configured target name
- eagerly fetch brand/category metadata for deterministic validation
- reject a known model when its dictionary category differs from the additional product category
- reject a known model when its dictionary target mode differs from the request
- validate SEARCH_QUERY targets using the configured search-query target name
- preserve legacy compatibility: unknown dictionary targets and models without category metadata are not blocked
- wire the guard into additional-target create/update validation

## Scope
Additional-product request validation only. No persistence schema, Playwright runtime, session, negotiation, quota or scheduler changes.

## Tests
New unit regressions cover matching category, category mismatch, SEARCH_QUERY lookup, target-mode mismatch, category-less legacy models and unknown legacy targets. Full repository CI is the merge gate.
