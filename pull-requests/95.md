## Description

Stage 15 hardens FIRST_OFFER success classification so backend state is advanced only after the marketplace exposes strong post-submit evidence.

Finding:
- after clicking the first-offer submit button, the worker historically treated navigation to any Vinted `/inbox/...` conversation as sufficient to mark the backend listing `NEGOTIATING/currentStep=1`;
- verification that the conversation actually contained our submitted offer was only best-effort and happened after the backend state change;
- that backend state is later used by the persistent guard/audit reconciliation as proof that the real action happened, so a redirect/UI race could create false positive proof.

Fix:
- add `SubmittedOfferConfirmationVerifier`, which waits for Vinted's own-offer price element and requires its parsed value to exactly match the submitted price;
- FIRST_OFFER now performs this strong confirmation before calling the backend listing update;
- if confirmation is missing/unreadable/mismatched after the real submit click, the existing post-quota failure path keeps the quota consumed and persistent FIRST_OFFER guard unresolved, so no automatic retry/resend is possible;
- normal own-offer status logging and optional text-message behavior remain unchanged after a confirmed backend update.

Verification:
- the dedicated real Chromium smoke renders the same own-offer `data-testid`, proves Polish-formatted price parsing/confirmation succeeds, and proves a displayed-price mismatch fails closed with `do not retry automatically` semantics.

Scope: Playwright only. No backend schema/API, target filters, quota semantics, selectors, or scheduler cadence changes.
