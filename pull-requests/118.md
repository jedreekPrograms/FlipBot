## Description

Follow-up to #117 based on the live bot-3 logs.

The explicit hard-block detector is working only when the block page text is actually rendered. In the live failure, Vinted kept the login form visible through all three deterministic submit mechanisms and then the job fell back to generic RUN_FAILED every 60 seconds.

This PR:
- keeps positive hard-block-page detection unchanged
- narrowly classifies the two known repeated Vinted auth-stall signatures as protective session cooldowns
- routes them through VintedSessionBlockedException so the existing persistent 15m -> 30m -> 1h -> 2h... bot-wide backoff applies
- prevents CATALOG_SCAN and NEGOTIATION_CHECK from continuing independently while the auth/session is effectively blocked
- leaves explicit wrong-password errors and unrelated failures on the normal RUN_FAILED path
- adds regression tests for direct/nested auth-stall classification

No database/schema change.
