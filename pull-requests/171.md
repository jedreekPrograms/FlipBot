## Description

## Problem
The current observer can now apply and persist the exact Vinted model filter, but it still re-validates every filtered row with the local title/URL matcher. That turns a valid exact-model catalog (for example Vinted showing hundreds of `iPad 10.9 (2022)` results) into `matched=0`. The UI then keeps Today / This week / Previous full week at zero or unavailable.

The current scanner also keeps reading the same first catalog batch instead of traversing Vinted's `page=` result pages.

## Changes
- trust the exact persisted Vinted category + brand + model filter for `VINTED_MODEL`; keep strict local matching for `SEARCH_QUERY`
- traverse filtered catalog pages while preserving the active Vinted filters, up to the configured safety limit
- inspect accepted listing detail HTML and read Vinted's own `Dodane ...` publication age / explicit publication date
- prefer the visible `Dodane` field and fall back to structured publication metadata only when needed
- store publication timestamps separately in `market_listing_observation.published_at`
- add a narrow idempotent local schema compatibility initializer for that column/index (Flyway remains untouched)
- keep a scan incomplete when a required listing publication time could not be resolved, so calendar stats are never silently guessed
- count Today from 00:00, This week from Monday 00:00, and Previous full week from the previous Monday-Sunday window using the Vinted publication timestamp
- make those calendar windows available immediately after a complete publication-enriched baseline instead of waiting a week from observer startup

## Scope
No changes to normal bot sessions, login/CAPTCHA behavior, negotiation actions, quotas, mobile connectivity, or normal catalog targeting. Publication enrichment is isolated to the anonymous read-only market observer.

## Tests
- publication parser covers minutes, hours, days and absolute timestamps
- observation context covers new listings and retrying known rows whose publication time is still missing
