## Description

## Co zmienia ten PR

Dodaje obserwacyjny dashboard runtime dla schedulera i botów, bez zmieniania logiki wykonywania jobów.

### Backend

Nowy endpoint:

`GET /api/dashboard/runtime`

Zwraca jednym requestem:

- liczbę wszystkich botów
- liczbę botów `RUNNING`
- liczniki `IDLE`, `QUEUED`, `WORKING`, `COOLDOWN`, `ERROR`
- średni czas ostatniego joba
- listę wszystkich botów z:
  - `botId`
  - nazwą
  - statusem biznesowym bota
  - runtime statusem
  - `lastRunStartedAt`
  - `lastRunFinishedAt`
  - `nextRunAt`
  - `lastRunDurationMs`
  - `consecutiveFailures`
  - `lastError`
  - `workerSlot`
  - `updatedAt`

Bot, który nie ma jeszcze rekordu telemetry, jest prezentowany jako `IDLE`; nie wykonujemy przy tym żadnego zapisu do bazy.

Endpoint korzysta ze zbiorczego `findAll()` dla botów i runtime state, a następnie składa dane w pamięci. Frontend nie wykonuje 1500 osobnych requestów `/runtime`.

### Frontend

- dodaje brakujący `frontend/src/api/dashboardApi.ts`, którego istniejący `DashboardPage` już używał
- zachowuje obsługę istniejącego `/api/dashboard/stats`
- dodaje klienta `/api/dashboard/runtime`
- dodaje stronę `/runtime`
- dodaje link `Runtime` w sidebarze
- auto-refresh co 5 sekund
- wyszukiwanie po nazwie lub ID bota
- filtr po runtime statusie
- tabela pokazująca status, worker slot, ostatni czas joba, next run, consecutive failures i ostatni błąd

Filtrowanie odbywa się lokalnie po pobraniu jednego snapshotu, więc wpisywanie w wyszukiwarkę nie generuje kolejnych requestów.

## Safety

PR jest tylko obserwacyjny. Nie zmienia:

- `BotRunScheduler`
- `BotWorkerSlot`
- `ScheduledBotRunExecutor`
- interwałów jobów
- real-offer flags
- negocjacji
- filtrów
- quota
- target matchingu

Nie dodaje też żadnych przycisków start/stop ani mutacji runtime.
