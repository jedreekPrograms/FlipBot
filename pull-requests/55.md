## Description

## Runtime problems confirmed from the latest production log

The supplied log showed three real runtime failures and several misleading/noisy diagnostics:

1. Bot 3 negotiation checks were healthy, but every `CATALOG_SCAN` repeatedly failed while resolving the exact `Galaxy S25` Vinted model option. The selector saw four partial model matches but the Playwright `hasText(regex)` approach did not resolve the exact visible label.
2. Bot 4's first S11 Ultra scan clicked the full category path but Vinted did not persist `catalog[]` before the outer verification, so the whole catalog job failed instead of retrying the category selection. A later retry did succeed.
3. Market Stats observer bot 5 submitted its login form twice but login verification depended on only `header-conversations-button`, causing a 30-second timeout and collector backoff.
4. `backend allows 0 new negotiations` was logged as an ERROR even though it is a normal reservation/capacity state.
5. Generic catalog failures delayed every scheduled job type for the bot, including negotiation checks. Only a real Vinted rate limit should pause all bot work.
6. Headful windows disappearing between scheduled jobs looked like browser crashes even though the reusable worker browser runtime stayed alive and only the per-job isolated BrowserContext was closed.

## Changes

- Exact Vinted model selection now polls the rendered model list for up to 10 seconds and compares **visible option text line-by-line**. It still fails closed and never accepts Edge/Ultra/FE/Plus as `Galaxy S25`.
- Exact-model failures now report the visible partial option labels, making future Vinted UI changes diagnosable.
- Added regression tests for multiline Vinted option text and variant rejection.
- Category selection now verifies `catalog[]` persistence inside its existing 3-attempt retry loop. A delayed/non-persisted first click is retried instead of immediately failing the whole catalog job.
- Intermediate category/brand retry messages are INFO; WARN is reserved for final retry failure or real page-safety events.
- Replaced the synthetic `document.body` mouse-event script used to dismiss the price drawer with native `Escape`, removing the `SyntaxError: Unexpected token ')'` seen in the log.
- Zero negotiation capacity is now an expected `NO_CAPACITY` INFO state. Real first-offer submit is disabled for that cycle, while discovery/history verification can still run.
- Normal READY/production execution messages are INFO instead of looking like faults.
- Generic job failure retries only the failed job type. A catalog failure no longer delays negotiation checks; explicit Vinted rate limits still pause all bot jobs.
- Worker errors are concise one-line ERROR entries with full stack traces moved to DEBUG.
- Added explicit browser lifecycle logging: each scheduled job closes only its isolated context/page; the worker-slot BrowserManager remains alive. With `headless=false`, a visible window disappearing between jobs is expected.
- Login verification now accepts multiple strong authenticated signals (`header-conversations-button`, visible `/inbox` link) plus a stable fallback where auth/login controls disappear on a trusted non-auth Vinted page. Post-submit verification waits up to 60 seconds and only then saves the session.
- Routine login DOM fallbacks are INFO rather than WARN.
- Market Stats failures now keep the one-line cause at ERROR and the full stack at DEBUG.

## Safety

No quota, negotiation decision, target-matching, encryption, or real-submit guard semantics are weakened. Exact model matching remains fail-closed. Only explicit rate limits retain global bot backoff.
