## Description

## Scope

Adds an explicit, fail-closed production switch for continuous real negotiations on the current `main`.

### Production mode
- adds `FLIPBOT_REAL_ACTION_PRODUCTION_MODE`
- adds dedicated confirmation `FLIPBOT_REAL_ACTION_PRODUCTION_CONFIRM=I_UNDERSTAND_CONTINUOUS_REAL_ACTIONS`
- production mode disables only the process-wide first-offer one-shot test lock
- per-run limits remain: max 1 real first offer per `CATALOG_SCAN`, max 1 real next step per `NEGOTIATION_CHECK`
- backend quota/idempotency, preflight, bot daily budget, scheduler isolation and retry handling remain unchanged

### Scalable bot scope
- adds `FLIPBOT_REAL_ACTION_ALLOW_ALL_RUNNING_BOTS`
- when `true`, it is valid only with correctly confirmed production mode
- this allows newly created bots to become real-action eligible simply by being switched to `RUNNING`
- outside production mode the all-running switch fails closed
- explicit `FLIPBOT_REAL_ACTION_BOT_IDS` remains supported for narrower production deployments

### Tests/docs
- adds unit tests for controlled mode, production allowlist mode, all-RUNNING mode, missing production confirmation, invalid all-running usage and preflight behavior
- updates `REAL_ACTION_TESTING.md` with the continuous production configuration, expected logs, emergency disarm and scaling notes

## Safety
- no backend business logic or migrations changed
- no negotiation policy changed
- no Vinted selectors/click flows changed
- no quota/idempotency guard removed
- STOPPED bots are still excluded by `WorkerManager`; all-running means all bots that the backend reports as RUNNING
- real-action configuration is still read at JVM startup, so changing flags requires a Playwright restart
