## Description

## What broke

A scheduler start could resolve the relative `sessions/` directory from a different working directory than manual session tooling. That makes valid `playwright/sessions/bot-X.json` files effectively invisible without deleting them. The workers then fall into interactive login together.

Separately, a repeated authentication-form stall was being promoted to `VintedSessionBlockedException` even without explicit block-page evidence, so multiple ordinary login stalls appeared in Runtime as `SESSION BLOCKED`.

## Fix

- resolve the default session directory from the Playwright module instead of raw process cwd
- support an explicit `FLIPBOT_SESSION_DIR` override
- discover the same module path from repo root, module root, or nested target/classes working directories
- log the absolute session directory once at startup for immediate diagnostics
- keep the non-destructive session backup behavior from #130
- stop promoting generic authentication stalls to `SESSION_BLOCKED`
- retain late explicit block-page polling, so real Vinted block evidence still uses the persisted session cooldown

## Regression coverage

- repository-root session path resolution
- module-root session path resolution
- nested target/classes resolution
- explicit session-directory override
- active session remains byte-for-byte intact during recovery
- repeated auth stalls remain generic failures rather than false session blocks
