## Description

## Problem
A market-stats pass currently starts from the first target every time. If Vinted returns HTTP 429 while scanning an early large model (for example iPad 10.9 (2022)), the observer backs off correctly but then retries from the same first model after cooldown. That can starve the remaining models indefinitely.

## Changes
- rotate the target order from an in-memory resume cursor
- remember the original target that was active when traffic backoff happened
- after HTTP 403/429/block-page backoff, resume from the following model after the 30-minute cooldown
- wrap around at the end of the target list so skipped/problematic models are revisited later instead of being abandoned
- reset to normal target order only after a full successful pass
- keep the existing full-catalog retry/backfill behavior from the backend API unchanged

## Scope
No change to normal bot scheduling, negotiation checks, session restore/save behavior, offer logic, backend persistence, or the 30-minute traffic-backoff policy. The observer still stops immediately on Vinted backoff; only the next starting model changes.
