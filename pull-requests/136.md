## Description

## What changed
- replace rolling 24h/7d planning metrics with calendar windows in Europe/Warsaw:
  - Today: 00:00 -> now
  - Current week: Monday 00:00 -> now
  - Previous full week: previous Monday 00:00 -> current Monday 00:00
- calculate required bots from the previous full week once that whole window is covered
- before a full previous week exists, estimate weekly volume from the average daily number of new listings observed since baseline, then scale to 7 days
- expose whether Today / Current week are only partial because baseline started after the window began
- keep baseline listings excluded from new-listing counts
- replace the price-matrix columns with Today / Current week / Previous full week / Required bots
- change the observer scheduler from the old 24h default to a 15-minute cooldown after a completed full pass
- keep the collector single-threaded so long scans never overlap; effective start-to-start spacing is pass duration + cooldown
- retain `FLIPBOT_MARKET_STATS_INTERVAL_HOURS` as a legacy fallback, while adding `FLIPBOT_MARKET_STATS_REFRESH_MINUTES`

## Recommendation semantics
- full previous week available -> exact previous-week listing count is the only input
- no full previous week yet -> `ceil(observed_since_baseline / tracked_calendar_days * 7)`
- one bot capacity remains 5 new conversations/day = 35/week

## Tests

- weekly projection from partial baseline data
- bot-capacity rounding
- refresh cooldown defaults, bounds, explicit override, and legacy compatibility
