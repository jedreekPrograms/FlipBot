## Description

## Cel

Zastępuje hardcoded `REAL_OFFERS_ENABLED=false` / `REAL_NEXT_STEPS_ENABLED=false` bezpieczną konfiguracją środowiskową dla kontrolowanego testu jednego bota.

Domyślnie scheduler nadal działa w 100% DRY RUN.

## Fail-closed safety gate

Realna akcja może zostać efektywnie włączona tylko wtedy, gdy jednocześnie są spełnione wszystkie warunki:

- `FLIPBOT_REAL_OFFERS_ENABLED=true` dla pierwszych ofert i/lub
- `FLIPBOT_REAL_NEXT_STEPS_ENABLED=true` dla kolejnych kroków
- `FLIPBOT_REAL_ACTION_BOT_ID=<pozytywny botId>`
- `FLIPBOT_REAL_ACTION_CONFIRM=I_UNDERSTAND_REAL_ACTIONS`

Brak poprawnego botId albo confirmation tokenu powoduje, że efektywny tryb pozostaje DRY RUN, nawet jeżeli flaga real action została ustawiona na `true`.

## Izolacja po typie joba

- `CATALOG_SCAN` może dostać wyłącznie `realOffers=true`
- `NEGOTIATION_CHECK` może dostać wyłącznie `realNextSteps=true`
- compatibility `executeOneRun()` zawsze pozostaje DRY RUN

Dzięki temu jeden full-run nie może przypadkowo wykonać obu rodzajów realnych akcji.

## Limity

Nadal twardo:
- `MAX_REAL_OFFERS_PER_RUN = 1`
- `MAX_REAL_NEXT_STEPS_PER_RUN = 1`
- `REAL_OFFER_ONE_SHOT_TEST_MODE = true`

## Logging

Scheduler loguje wyraźnie:
- `DRY RUN mode`, albo
- `CONTROLLED REAL ACTION MODE`

oraz efektywne flagi dla konkretnego joba/bota.

## Safety

PR nie włącza żadnej realnej akcji sam z siebie. Bez env-ów powyżej zachowanie pozostaje dry-run.

Nie zmienia:
- persistent action guardów FIRST_OFFER/NEXT_STEP
- quota semantics
- target matchingu
- filtrów / `FilterActions`
- popup guarda
- scheduler queue/priority
- Buy now / ACTION_REQUIRED flow
