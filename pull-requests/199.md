## Description

## Problem
Worker slots kept headless Chromium runtimes warm between jobs for up to the configured idle timeout. With many RUNNING bots and a steady queue, every slot could receive work frequently enough that none of the browser runtimes reached the idle timeout. This left up to the full worker count of Chromium process trees resident in memory even when only a few bots were actually WORKING.

## Fix
- release the BrowserManager after every completed scheduled job in both headless and headful modes
- keep worker slots themselves alive and queue-aware, but without retaining Chromium while waiting
- rely on the existing validated `bot-X.json` storage state for the next job, so authentication remains independent of browser-process lifetime
- keep null-runtime cleanup idempotent

## Scope
No SessionManager, login, scheduler cadence, negotiation, quota, backend or frontend behavior changes.

## Validation
- retention tests now require both headless and headful runtimes to close after a job
- full repository CI is the merge gate, including the existing Playwright session persistence/restore tests
