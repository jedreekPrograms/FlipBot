## Description

## Why
It is hard to tell from runtime logs whether a bot is using Vinted's structured model filter or the main text search, and the existing model-option click used a substring match (`hasText(model).first()`), which could in principle click a sibling variant such as `Galaxy S25 Edge` when the configured model is plain `Galaxy S25`.

## Changes
- add a prominent `[BOT TARGET FLOW]` banner before every catalog cycle
- for `SEARCH_QUERY`, log that main Vinted text search is active, the exact query that will be typed, and that the model filter is skipped
- for `VINTED_MODEL`, log that text search is skipped, the exact configured model, and the structured sequence category -> brand -> Vinted model filter -> price -> newest
- log the final verified catalog URL after filters are applied
- make Vinted model-option selection fail closed unless an exact model label is found
- log the exact visible option text and `data-testid` that is clicked
- explicitly refuse partial matches such as Edge / Ultra / FE / Plus
- add regression tests for exact model-option matching

## Existing guarantees confirmed
`SEARCH_QUERY` already fills `form[action='/catalog'] input[name='search_text']`, reads the value back, presses Enter, and verifies `search_text` in the URL. `VINTED_MODEL` skips that path, opens the model filter, searches the model there, confirms it, and verifies `brand_collection_ids[]` in the URL. This PR makes that behavior much more visible and makes the model click itself exact rather than substring-based.
