## Description

## Problem
After the field-aware editing change, the global negotiation cap was technically editable during active negotiations, but the UI/backend still treated the highest already-sent offer as a hard minimum. That made it impossible to lower the cap below an offer that had already been sent.

## New semantics
The global negotiation cap is future-facing:
- lowering it does **not** retract an offer already sent to Vinted,
- all later adaptive escalations still respect the new cap,
- the cap may be lower than the current active offer,
- the cap still cannot be lower than the configured first negotiation step, because a newly-started negotiation would otherwise begin above its own cap.

Example: configured ladder starts at 900 zł, active offer is already 1050 zł. The cap can now be changed from 1200 zł to 1000 zł. The existing 1050 zł offer remains, but the bot will not send a later automatic escalation above 1000 zł.

## Changes
- backend edit capabilities now expose the first configured offer as the minimum valid cap instead of the highest active offer,
- removed the backend restriction against lowering below an already-sent active offer,
- updated the UI explanation so it is clear that earlier offers are not retracted,
- added backend coverage for lowering the cap below a live offer,
- added Playwright decision coverage proving a lowered cap stops future escalation.
