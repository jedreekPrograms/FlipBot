## Description

## Cel

Pozwala bezpiecznie dopuścić więcej niż jednego bota do schedulerowych real actions bez usuwania istniejących guardów i limitów.

## Nowa konfiguracja

Nowy env:

`FLIPBOT_REAL_ACTION_BOT_IDS=3,4`

- lista jest rozdzielana przecinkami,
- wszystkie ID muszą być dodatnimi liczbami,
- jeden błędny wpis wyłącza całą allowlistę fail-closed,
- wymagany nadal jest dokładny token `FLIPBOT_REAL_ACTION_CONFIRM=I_UNDERSTAND_REAL_ACTIONS`,
- `FLIPBOT_REAL_ACTION_PREFLIGHT_ONLY` nadal działa dla całej allowlisty.

## Backward compatibility

Stary `FLIPBOT_REAL_ACTION_BOT_ID` nadal działa jako fallback, jeśli `FLIPBOT_REAL_ACTION_BOT_IDS` nie jest ustawione.
Jeżeli oba są ustawione, nowa lista ma pierwszeństwo i stary env jest ignorowany.

## Safety

Nie zmienia:
- persistent FIRST_OFFER / NEXT_STEP guardów,
- quota semantics,
- process-wide one-shot per bot,
- `MAX_REAL_OFFERS_PER_RUN=1`,
- `MAX_REAL_NEXT_STEPS_PER_RUN=1`,
- target matchingu,
- negotiation timers/decisions,
- popup guarda,
- headless schedulera.

Dzięki temu bot 3 i bot 4 mogą być jednocześnie uzbrojone, ale każdy zachowuje własną blokadę one-shot i własny backendowy action guard.
