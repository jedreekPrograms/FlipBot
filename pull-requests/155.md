## Summary
- turn the existing React frontend into an installable phone-first PWA while preserving the complete desktop feature set
- add polished mobile navigation covering the current Dashboard, Runtime, Bots, offers, history, pricing and dictionary workflows
- add a dedicated CAPTCHA queue and remote manual browser viewer
- keep the browser and bot session on the PC; the phone only relays the user's direct pointer/touch gesture to the active headed Playwright page
- add a loopback-only Playwright control bridge and a Spring proxy so the Playwright `Page` is never accessed from arbitrary HTTP threads
- preserve the existing `bot-X.json` recovery/save/resume lifecycle

## Manual CAPTCHA flow
`CAPTCHA_REQUIRED -> phone CAPTCHA queue -> start recovery -> PC opens headed browser with the same session -> real challenge becomes visible -> phone receives current browser frames -> user's DOWN/MOVE/UP gesture is queued -> owning Playwright thread applies it -> verification clears -> session is saved -> bot resumes headless`

The remote control deliberately does not choose or synthesize a CAPTCHA solution. It maps the user's actual gesture onto the browser viewport.

## Connectivity
The app continues to use relative `/api` routes. Remote phone access is intended through a private network such as Tailscale rather than exposing the Playwright bridge publicly; the Playwright bridge itself only binds to loopback.
