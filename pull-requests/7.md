## Description

## Co zmienia ten PR

- zmienia główny runtime z modelu `1 RUNNING bot = 1 nieskończony worker` na scheduler + stałą pulę reusable worker slots
- dodaje `DelayQueue`, która planuje następne uruchomienie bota zamiast trzymać jego worker bez końca
- gwarantuje maksymalnie jeden stan `QUEUED` albo `WORKING` na bot, więc ten sam bot nie trafi równolegle do dwóch slotów
- `STOP` usuwa job z kolejki; jeżeli bot już jest `WORKING`, kończy bieżący run i nie dostaje następnego
- szybkie `STOP -> START` nie tworzy duplikatu: bot pozostający `WORKING` zostanie zaplanowany ponownie dopiero po zakończeniu bieżącego runa
- każdy worker slot ma własny długowieczny `Playwright` + `Chrome` na jednym wątku
- każdy bot dostaje osobny `BrowserContext`, własny `sessions/bot-{id}.json`, jeden `executeOneRun()`, zapis sesji i zamknięcie contextu
- slot po zakończeniu bota bierze kolejnego bota z kolejki
- usuwa stary `BotWorkerRuntime`, który reprezentował model jednego runtime na jednego bota

## Konfiguracja

Domyślnie:

- `FLIPBOT_WORKER_COUNT=10`
- `FLIPBOT_SYNC_INTERVAL_SECONDS=5`
- `FLIPBOT_RUN_INTERVAL_SECONDS=30`
- `FLIPBOT_FAILURE_RETRY_SECONDS=60`
- `FLIPBOT_RATE_LIMIT_RETRY_SECONDS=600`
- `FLIPBOT_SHUTDOWN_TIMEOUT_SECONDS=30`

`FLIPBOT_WORKER_COUNT` można później zwiększać podczas benchmarków bez zmiany kodu.

## Safety

Scheduler mode jest celowo wymuszony na:

- `REAL_OFFERS_ENABLED = false`
- `REAL_NEXT_STEPS_ENABLED = false`

Nie korzysta z manualnych flag starego continuous workera, więc ta zmiana sama w sobie nie może włączyć realnych ofert ani kolejnych kroków negocjacji.
