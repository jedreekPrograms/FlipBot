## Description

## Problem

Three runtime issues showed up together in the latest local logs:

- Market stats can successfully apply the exact Vinted filter and discover a large filtered catalog, but a 403/429 while resolving publication times aborts the model before `recordObservations`, so all progress from that model is lost. Incomplete retries also re-requested publication timestamps that were already stored.
- A normal bot job can return normally even after individual conversation navigations degrade into `/session-refresh`. Because the outer job is still marked successful, that degraded browser state could replace `bot-X.json`. Bot 11 then repeatedly entered interactive login stalls on the next jobs.
- FlipBot Mobile accepted a persisted literal `undefined`/`null` as a server address and normalized it to a hostname such as `http://undefined`, producing `net::ERR_NAME_NOT_RESOLVED`.

## Changes

### Market stats
- Resolve `created_at_ts` from the already-loaded filtered catalog hydration first, without issuing item-detail requests.
- Reuse already persisted publication timestamps during full catalog retries; only new/missing timestamps are resolved again.
- Limit the item-detail fallback to a very small paced sequential batch and keep the existing fail-closed 403/429 backoff.
- Preserve observed listing IDs and any timestamps resolved before an interrupted scan, then persist that partial progress with `complete=false` before clearing the observation context.
- Keep exact Vinted-model filtering and full-catalog traversal requirements unchanged.

### Session persistence
- Capture a verified authenticated checkpoint immediately after `LoginService` succeeds.
- Before the final session save, require a strong authenticated Vinted signal; `/session-refresh`, login/register UI, or an ambiguous end state is not allowed to replace the active session.
- Add a rotating last-known-good restore path. The rejected active state is preserved as the rotating recovery snapshot before rollback.
- When a known authentication stall triggers protective cooldown, try to restore last-known-good rather than repeatedly starting from the same degraded active session.

### Mobile
- Reject empty, malformed, `undefined`, `null`, and `nan` hosts.
- Clear an invalid persisted server URL and open connection settings instead of loading it in the WebView.
- Surface the native WebView error code/description in the connection banner.

## Scope / safety
- No CAPTCHA or anti-bot bypass changes.
- No relaxation of exact model verification.
- Normal bot negotiation/catalog logic is unchanged apart from safer session persistence and recovery.
- Market observer traffic is reduced, not increased.

## Tests
- Catalog timestamp extraction script is verified to use current page hydration and make no network calls.
- Detail fallback pacing/backoff script expectations updated.
- Last-known-good rollback preserves the rejected active state as recovery and leaves active untouched when no backup exists.
- Full repository CI will validate Playwright, backend, frontend, and mobile builds.
