## Description

Full audit follow-up focused on the remaining session-loss paths found in the 2026-09-18 production log.

Session hardening:
- hold an OS-level exclusive lock for the active Playwright session directory for the entire JVM lifetime, so an accidentally started second FlipBot Playwright process cannot concurrently schedule the same bots or replace the same bot-X.json files;
- remember whether a production browser context actually restored persisted session state;
- give a restored session a bounded ~8s authentication-UI stabilization window before falling back to credential login; no cookies/storage/session file are cleared during this grace period.

Negotiation hardening discovered in the same audit:
- reject seller-counteroffer DOM evidence when the parsed counter is above the listing's captured original price; the state becomes UNKNOWN/fail-closed instead of driving a price decision;
- preserve the strict prepared next-step conversation identity guard, but include expected/actual conversation id and URL in the failure for the repeated S25 FE case.

Regression coverage:
- second JVM/session-directory owner is rejected and lock becomes reusable after shutdown;
- delayed authenticated UI wins during restored-session grace and the grace period is bounded;
- implausible counteroffer 2346.19 vs original 1091.18 is rejected, while normal counteroffers remain accepted.

This intentionally does not relax any real-offer or next-step fail-closed guard.
