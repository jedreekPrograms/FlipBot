## Description

Stage 11 fixes one worker-slot recovery gap without changing normal browser reuse.

Finding:
- each BotWorkerSlot intentionally reuses one BrowserManager across jobs;
- job exceptions are isolated correctly, but if the underlying Chromium process disconnects/crashes, the slot historically kept the same non-null BrowserManager;
- later jobs could therefore keep trying to create contexts against a dead Browser and repeatedly fail even though the scheduler/thread itself remained alive.

Fix:
- BrowserManager exposes an owner-thread-only `isHealthy()` check backed by Playwright `Browser.isConnected()`;
- before a claimed job reuses the browser runtime, BotWorkerSlot checks that connection;
- only a disconnected runtime is closed/discarded and replaced lazily with a fresh BrowserManager;
- ordinary page timeouts, selector failures, backend errors and rate limits do not restart a healthy browser runtime.

Verification:
- the existing real Chromium encrypted-session smoke now asserts the BrowserManager health probe before and after context/session work.

Scope: 3 Playwright files only. No backend/database/frontend, selectors, target logic, quotas, guards, or real-action semantics changed.
