## Description

## Problem
Additional-product rows are intentionally retained after deactivation so existing conversations can keep their original strategy. However, the Playwright payload currently includes every inactive historical product forever, even after all runtime negotiation work has finished. Over time this makes every negotiation check iterate across stale product configurations that no longer have work.

## Changes
- keep all additional-product rows in PostgreSQL; no history is deleted
- keep all active additional products in the Playwright payload
- keep an inactive additional product only while it still owns a `NEGOTIATING` listing
- do not retain inactive products merely because they are `ACTION_REQUIRED`; at that point FlipBot no longer sends negotiation steps for that conversation
- load the relevant inactive target ids in one backend query instead of one query per target
- add regression coverage for active, inactive-with-live-negotiation, and inactive-historical products

## Compatibility
Existing negotiations from a disabled product still retain their original strategy across Playwright restarts. Once the negotiation leaves `NEGOTIATING`, the historical target remains stored in PostgreSQL but is no longer sent through the runtime payload.
