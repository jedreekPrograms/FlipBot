## Description

## Root cause
The captured Vinted DOM confirms the visible checkbox is inside `.u-no-pointer-events`. A normal Playwright click on the nested checkbox/control is therefore not equivalent to a real user click, and clicking the row center is not reliable enough for this component.

## Fix
- Keep exact model / exact collectionId proof unchanged.
- Locate the exact checkbox for the proven `brand_collection_ids[]` value.
- Use the visible sibling checkbox square only to obtain screen coordinates.
- Send a real mouse click at the square center. Because that subtree has `pointer-events:none`, Chromium hit-testing delivers the click to the canonical selectable Cell, matching a real user click.
- Verify the exact proven native checkbox became checked before continuing.
- Keep short row click, DOM row click, keyboard, and exact-input DOM activation as bounded fallbacks.
- Make the exact native checkbox authoritative when it exists, so generic row/custom state cannot produce a false positive.

## Safety
Exact matching remains fail-closed. `Galaxy S25`, `Galaxy S25 FE`, `Galaxy S25 Edge`, and `Ultra` are still separate targets, and persistence is still verified with the exact `brand_collection_ids[]` value.
