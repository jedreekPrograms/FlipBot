## Description

## Problem
Fresh production logs show the dedicated market-stats collector starting normally, then failing before the first model is scanned:

`MarketStatsCollector.prepareObserverCatalogSession()` calls `MarketplaceNavigator.goToCatalog()` and immediately waits for the browser's full `load` state again. `MarketplaceNavigator` already navigates with `DOMContentLoaded` and probes the catalog shell, so this second wait is redundant. On Vinted, ad/analytics/third-party resources can keep the page loading past 30 seconds even though the catalog DOM is ready, causing the whole market-stats pass to abort and leaving Today / This week unchanged.

The same full-load dependency existed when opening page 2+ of a filtered catalog.

## Changes
- remove the redundant full `load` wait after the observer opens `/catalog`
- keep `MarketplaceNavigator` as the readiness authority for the initial catalog page
- navigate filtered catalog pagination with `waitUntil=DOMContentLoaded` and a bounded 30s navigation timeout
- keep the existing short post-navigation settling delay before scanning listings
- add a regression test for the pagination navigation options

## Scope
Market-stats observer navigation only. No changes to normal bot sessions, login/CAPTCHA, negotiations, real actions, quotas, filters, or mobile connectivity.

## Expected behavior
A usable Vinted catalog no longer gets rejected solely because non-essential resources prevent the browser's full `load` event. The observer should reach model scans, allowing incomplete publication-time backfills and new observations to actually run.
