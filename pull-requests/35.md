## Description

## Problem

Najnowszy realny log observera doszedł do wszystkich 23 modeli, ale zakończył rundę z `recorded=20, failed=3`. Dwa widoczne błędy (`Motorola Edge 70` i `Galaxy Tab S11 Ultra`) miały ten sam root cause: po poprawnym wejściu w text-only fallback `FilterService` próbował kliknąć `#sort_by-list-item-newest_first`, element nie pojawiał się w 10 s i timeout przerywał cały model.

Mieliśmy już URL fallback dla sytuacji, gdy kliknięcie sortowania się udało, ale Vinted nie utrwalił `order=newest_first`. Nie obejmował on jednak timeoutu samego UI.

## Fix

`applySortBy()` teraz:
- nadal najpierw próbuje standardowe UI Vinted,
- jeśli UI nie utrwali sortowania, używa istniejącego URL fallbacku,
- jeśli UI rzuci wyjątek/timeout, ale page nadal żyje, również przechodzi do URL fallbacku,
- jeśli page jest faktycznie zamknięty (`page.isClosed()`), propaguje wyjątek i nie maskuje awarii browsera,
- po URL fallbacku nadal weryfikuje, że `order=newest_first` naprawdę jest w URL.

## Safety

Zmiana dotyczy wyłącznie sortowania katalogu w `FilterService`. Nie zmienia target matchera, market-stat baselines, negocjacji, real actions, quota, guardów ani schedulerów.

## Expected effect

Przypadki z logu, gdzie text-only fallback kończył się wyłącznie timeoutem `#sort_by-list-item-newest_first`, powinny teraz kontynuować skan modelu zamiast oznaczać go jako failed.
