## Full audit — stage 2: configuration / credentials / transport

This stage keeps the existing local architecture working while removing unsafe defaults and legacy credential storage hazards.

### Security and configuration
- backend binds to `127.0.0.1` by default
- PostgreSQL development port binds to host loopback only
- datasource/server settings are environment-overridable
- API security is explicitly stateless; unused HTTP Basic removed
- repository ignores generic env/key/runtime secret material
- `.env.example` documents required encryption-key generation and runtime variables

### Credential hardening
- startup migration encrypts legacy plaintext `bot.password` rows in-place
- ciphertext detection validates AES-GCM with the configured key instead of trusting only the `enc:v1:` prefix
- concurrent application startup is handled safely
- no credential values are logged

### Worker transport
- `FLIPBOT_BACKEND_URL` replaces the hardcoded backend origin
- plaintext HTTP is allowed only for loopback hosts
- remote backend communication requires HTTPS
- malformed origins / embedded credentials / extra paths are rejected
- all interrupted HTTP calls restore the thread interruption flag

### Tests
- credential migration unit coverage
- backend endpoint transport validation coverage

Stage 3 will address the remaining mixed Hibernate/Flyway schema ownership rather than changing `ddl-auto` prematurely and breaking fresh databases.
