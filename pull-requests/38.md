## Description

## What changed

- recover filter flows immediately when the main browser page is hijacked to an external/ad domain
- restore a last-known safe Vinted URL **before propagating filter errors**, so existing sort/price URL fallbacks can never append Vinted parameters to an external URL
- make category/filter reload recover to the last trusted Vinted page instead of reloading an ad page
- make Vinted host/catalog validation URI-based and HTTPS-only instead of permissive string matching
- use the same strict host validation for popup/page classification
- retry only bounded, transient Vinted navigation failures (`ERR_NETWORK_CHANGED`, `ERR_NAME_NOT_RESOLVED`, connection reset/timeout, interrupted navigation)
- detect stopped worker-slot futures during scheduler sync and recreate missing concurrency capacity when RUNNING bots still require it
- add lightweight tests for trusted/lookalike/external/non-HTTPS URL classification
- add `playwright/REAL_ACTION_TESTING.md` with a staged DRY RUN -> PREFLIGHT ONLY -> one real action -> multi-bot test ladder

## Why

The latest runtime log completed all 76 market-stat targets successfully, but one primary filter flow was repeatedly redirected from Vinted to `sos-accessoire.com` before the existing fallback recovered. The same log also proves two scheduler jobs can already run concurrently (`working=2`). Before enabling any real-action flags, this PR hardens the browser/filter boundary and makes worker-slot capacity self-healing.

## Safety

- no real-action flag is enabled by this PR
- existing exact confirmation token and bot allowlist are unchanged
- `PREFLIGHT_ONLY` behavior is unchanged
- max 1 real first offer per catalog run remains unchanged
- max 1 real next step per negotiation-check run remains unchanged
- first-offer one-shot test mode remains unchanged
- no production/continuous-real-action branch is merged

## Validation

- branch is based directly on current main
- reviewed scheduler state machine: one bot remains QUEUED or WORKING, never both
- current runtime log already demonstrated two different bots working simultaneously on two slots
- URL safety unit tests cover Vinted, external URLs, lookalike hosts, non-HTTPS URLs and catalog-path validation
- reviewed the external-redirect path through category, brand, model, sort and price actions; URL fallbacks see a restored trusted URL after page-safety failure
- repository has no configured CI checks; local Maven execution is still unavailable in the assistant environment because its container cannot resolve GitHub/Maven dependencies
