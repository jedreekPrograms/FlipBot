## Description

## Cel

Podłącza trwały `real_action_guard` z PR #16 do realnego `NEXT_STEP`.

Scheduler nadal pozostaje DRY RUN — ten PR nie włącza realnych next-stepów ani pierwszych ofert.

## Nowa kolejność NEXT_STEP

Dla decyzji `SEND_NEXT_STEP` w real mode:

1. acquire persistent `NEXT_STEP` guard
2. reserve daily quota
3. wejście w `NextNegotiationStepExecutor.sendNextStep()`
4. real submit
5. backend zapisuje nowy `currentStep`
6. po potwierdzonym `SENT` guard jest czyszczony best-effort

## Fail-closed

### Guard blocked
- quota NIE jest rezerwowana
- real submit NIE jest wykonywany

### Błąd / brak quota przed real submit
- guard jest zwalniany
- real submit NIE jest wykonywany

### `OFFER_TOO_LOW`
- executor nie wysyła oferty
- quota jest zwalniana
- guard jest zwalniany

### Błąd po wejściu w real `sendNextStep()`
- quota NIE jest automatycznie zwalniana
- guard NIE jest zwalniany
- kolejny scheduler run nie może bezwarunkowo powtórzyć tej samej realnej akcji

### `SENT`
- backend ma potwierdzony nowy krok
- guard jest usuwany best-effort
- jeśli cleanup się nie uda, backendowy guard potrafi później rozpoznać stale guard po `NEGOTIATING/currentStep`
