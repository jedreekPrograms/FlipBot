## Description

The Bots panel issued two requests per bot every five seconds, including quota reads that lock bot rows. Runtime also rerendered the entire table every second, and overlapping refreshes could race with session-preview changes.

This adds a read-only, single-statement activity snapshot and reuses the existing runtime snapshot, reducing recurring Bots activity/runtime requests to two per refresh. Polling is serialized, pauses and aborts reads while hidden, and resumes on return. Manual refreshes after preview changes wait for a fresh request. Per-bot pending state protects Show/Hide controls when several bots are updated. Only blocked runtime rows need the one-second clock.

The snapshot retains the existing counters, 0–25 display limit, durable request deduplication, original reservation-day accounting, and conservative persisted usage. The authoritative offer quota guard, session files, browser lifecycle and database schema are unchanged by the new performance commit.
