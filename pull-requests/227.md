## Description

A quick STOP followed by START could retain a session preview because cleanup depended on the scheduler observing the stopped bot. Ordinary job failures also reported the configured 60-second fallback before adaptive backoff, then immediately replaced ERROR with QUEUED.

This change clears a bot's preview directly on STOP and publishes one failure event after the scheduler calculates the effective retry. The event is enqueued before another worker can claim the bot, preserving telemetry order. Browser/session persistence, marketplace actions, cadence and cooldown rules stay as they are.

Regression coverage includes rapid STOP/START, actual 2/5-minute retry deadlines, reset after success, independence from successful negotiations, bot-wide cooldowns, and failure completion after STOP. An injected clock makes scheduler tests deterministic. Full CI is required before merge.
