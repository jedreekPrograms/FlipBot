## Description

## Problem
Fresh observer logs show catalog scans completing, but publication-time enrichment crashes inside `MarketListingPublishedAtResolver.captureIfNeeded()` with `SyntaxError: Invalid regular expression: missing /`. That exception prevents `published_at` from being resolved, so calendar counters remain 0 even though listings are being scanned.

The regression came from the hydrated `created_at_ts` JavaScript parser added after the original publication-time resolver. Java text-block escaping turns its character-class regex into invalid JavaScript at runtime.

## Fix
- restore the previously working publication-time resolver implementation from before the broken hydration optimization
- keep the current backend publication-time/backfill/counting semantics unchanged
- keep OneTrust, sessions, login, CAPTCHA, negotiation and observer scheduling unchanged

This intentionally removes only the broken `created_at_ts` optimization; JSON-LD / visible `Dodane` extraction continues to resolve Vinted publication times as before.
