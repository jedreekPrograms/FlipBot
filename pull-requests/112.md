## Description

## Problem
Each bot already loads its own `DISCOVERED` pool by `botId`, but a persisted pool can contain historical wrong-model rows from an old filter bug or a later configuration change. The runtime then incorrectly treated every VINTED_MODEL backlog row as if it still had proof from the *current* exact Vinted model filter. This allowed examples such as Galaxy Tab S9 FE+ to reach a Galaxy S25 negotiation.

## Architecture after this fix
Target ownership, queue priority, and model proof are now three separate concepts:

1. **Bot ownership / pool** — backend `getDiscoveredListings(botId)` remains strictly per bot.
2. **Fresh vs backlog** — used only for fair queue ordering.
3. **Current target provenance** — only marketplace IDs actually observed in THIS already-filtered current catalog scan inherit current exact-model proof.

A previously persisted DISCOVERED row that is not in the current result set cannot claim `EXACT_VINTED_MODEL_FILTER` just because it belongs to an S25 bot. It must prove the current S25 identity again from stored evidence or the live item page.

## Fix
- carry `currentScanListingIds` alongside the bot-scoped persisted backlog
- stop blindly treating every VINTED_MODEL backlog row as an exact-model match
- classify persisted catalog title / URL as MATCH, MISMATCH or NEEDS_DETAIL_INSPECTION
- distinguish positive configured-model proof from merely “not a mismatch”
- read structured Vinted `Marka` / `Model` values from the live item page
- fail closed on generic/ambiguous historical listings when no structured model proof can be read
- add a final structured identity gate immediately before quota / real submit
- reject current-scan rows too when their stored title contains conclusive conflicting-model evidence
- prevent additional steps for existing negotiations with conclusive wrong-model title/URL evidence
- preserve valid generic historical negotiations instead of terminating them without proof
- add regression tests for Galaxy Tab S9 FE+, Fold5, S25 variants, generic titles, structured field parsing and existing-negotiation protection

## Safety
No backend schema change. No listing/audit history deletion. Wrong persisted DISCOVERED candidates are fail-closed before quota/submit and conclusive mismatches are persisted as `SKIPPED_TARGET_MISMATCH`.
