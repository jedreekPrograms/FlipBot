## Description

The intentional rollback to PR #221 removed the Runtime Show/Hide session controls. The user now requests those controls back while preserving the working rollback version.

This is a single commit based directly on 8d869b2. It restores only the preview flag, Runtime controls and propagation through the existing worker sync. The selected bot launches its next normal scheduled job in a visible window, and Chromium still closes after the job. STOP clears that bot's pending preview immediately, including rapid STOP/START. The UI tracks saves independently per bot and ignores older runtime responses that could overwrite a newer button state.

The scheduler algorithm, category selectors, offer/quota guards, login/CAPTCHA, SessionManager, service-worker settings and database schema remain identical to the rollback base. The broader performance experiment in #233 was closed without merging after recovering the user's rollback instructions.

Validation: local ESLint and TypeScript/Vite production build pass, with the existing unrelated hook warning. Regression tests cover preview enable/disable, per-bot isolation, removal from running-bot sync, API/dashboard-to-worker propagation, registry clearing and rapid STOP/START. Require full Backend / Frontend / Mobile / Playwright unit CI before merge. Then verify the existing mobile-web-panel bundling workflow so Spring Boot serves the updated controls.

Behavior: Show affects the next scheduled job; it cannot reveal an already-running headless job. Hide affects subsequent jobs and lets the current job finish. No extra browser, immediate job or authentication session is created.
