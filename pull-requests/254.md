## Description

Full-audit database scaling fix.

Adds a deliberately small index set for the query patterns used constantly by scheduler/UI:
- `(bot_id, status, id)` for per-bot lifecycle scans/counts;
- `(status, id)` for global status/action-required reads;
- partial visible-history `(status, decision_at DESC, id)` for dashboard/history reads.

The existing unique `(bot_id, listing_id)` index does not cover these access paths efficiently. No schema semantics, statuses, constraints or application logic change.
