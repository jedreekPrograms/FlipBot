## Description

## Co zmienia ten PR

- dodaje `BotRunExecutor` z publicznym `executeOneRun()`
- przenosi dokładnie jeden logiczny cykl pracy z `BotWorker.doWork()` do tego executora
- `BotWorker` pozostaje kompatybilnym wrapperem odpowiedzialnym za login, nieskończoną pętlę, sleep, rate-limit cooldown i shutdown
- mierzy czas każdego pojedynczego runa w ms, co później posłuży do dobrania liczby worker slotów dla dużej liczby botów

## Zachowanie, które pozostaje bez zmian

- `REAL_OFFERS_ENABLED = false`
- `REAL_NEXT_STEPS_ENABLED = false`
- test bot ID = 4
- one-shot real-offer guard
- `MAX_REAL_OFFERS_PER_RUN = 1`
- `MAX_REAL_NEXT_STEPS_PER_RUN = 1`
- najpierw istniejące negocjacje, potem katalog
- jeśli realny next step został wysłany, katalog w tym runie jest pomijany
- rate limit nadal powoduje 10-minutowy cooldown obecnego workera
- `BotContext` nadal jest zamykany przez `BotWorker` w `finally`

## Dlaczego

To jest etap przejściowy przed schedulerem. Następny etap będzie mógł wywołać dokładnie jeden `executeOneRun()` i po zakończeniu oddać worker slot innemu botowi, bez kopiowania lub przepisywania logiki negocjacji i katalogu.

## Zakres

PR zmienia tylko:
- `BotWorker.java`
- nowy `BotRunExecutor.java`

Nie zmienia żadnego processora negocjacji, skanowania, filtrów, target matchingu ani quota.
