## Summary
- for non-final negotiation steps, treat prolonged Vinted PENDING as no formal response
- wait exactly 2x the current step's configured rejection wait before allowing the next step
- current ladder therefore becomes: step 1 12h, step 2 12h, step 3 16h, step 4 32h
- preserve final-step behavior: 48h PENDING -> EXPIRED
- if a rejection policy has no positive wait (e.g. NEXT_STEP_NOW/legacy), use a conservative 12h no-response fallback
- keep adaptive pricing/global cap checks before the timed PENDING step can be sent
- stale legacy PENDING conversations will progress only through the normal real-action guard + daily quota path
- add regression tests for timeout and pre-timeout waiting

## Safety
No session persistence or hard daily quota code is changed. A timed PENDING next step still uses the same preparation, action guard, quota reservation, Vinted confirmation and backend update path as a normal next step.
