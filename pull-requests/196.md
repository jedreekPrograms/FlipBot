## Description

## Problem
A bot can now own MAIN plus up to four additional products with independent categories, but the shared product form loaded every model for the selected brand regardless of the selected category. Changing category also left the old selected model in the form until another action cleared it. That could create an inconsistent category/model combination in the UI.

## Fix
- filter model choices against the selected dictionary category
- reset the selected model immediately when category changes
- require category selection before model selection
- keep legacy dictionary models with no category metadata visible so existing configurations remain editable
- use category path metadata as a fallback when a model has path metadata but no category id

## Scope
Frontend form safety only. No scheduler, Playwright runtime, session, negotiation, quota, or backend persistence changes.

## Validation
Frontend lint/build plus full repository CI are the merge gate. A separate follow-up will add server-side category/model consistency validation so direct API calls cannot bypass the UI guard.
