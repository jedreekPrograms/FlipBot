## Description

## Scope

Deep negotiation audit/fix on top of stable `4bf244ef`. This PR is intentionally limited to conversation/negotiation integrity and does not change catalog category/filter selection.

## Confirmed issues fixed

- Explicit Vinted `PENDING` offers could become `EXPIRED` after 48h and disappear from active negotiations even though Vinted still showed them as pending.
- A read indicator or ordinary seller chat message could trigger a hidden 3h automatic price increase while the previous offer was still formally pending.
- Three ambiguous checks with missing composer/offer controls could terminalize a conversation as `CONTACT_UNAVAILABLE` without explicit block/contact-disabled evidence.
- Seller counteroffers could become `REJECTED` when there was no safe automatic next step, even though the seller had made an actionable live price proposal.
- Vinted status parsing only recognized narrow Polish forms (`Oczekujące/Zaakceptowane/Odrzucone`).
- A DOM price misread above the original listing price could be treated as a seller counteroffer.
- First-offer and conversation navigation did not consistently use the shared session-refresh-safe navigator.
- Non-adaptive negotiation ladders were not required by backend validation to be strictly increasing.
- Runtime next-step validation did not reject a price <= the current sent offer.
- A real first offer could succeed on Vinted while redirect/backend persistence failed after the click, leaving the listing outside `NEGOTIATING`.

## Behavior after this PR

- While Vinted explicitly says the latest own offer is pending, the listing stays `NEGOTIATING` indefinitely. Read/message/time alone never raises the price and never terminalizes it.
- Only formal rejection/counteroffer policies advance the ladder. Their configured waits remain authoritative.
- Seller counteroffer with no safe automatic next step becomes `ACTION_REQUIRED`, not `REJECTED`.
- Only explicit block/contact-disabled evidence may set `CONTACT_UNAVAILABLE`; ambiguous missing controls remain active and retry later.
- Status variants are matched by stable stems; impossible seller prices fail closed as UNKNOWN.
- First-offer ambiguous post-submit recovery is allowed only with strong item-bound conversation URL evidence plus the exact expected latest own-offer price; it never clicks submit again.
- Existing `EXPIRED` / `CONTACT_UNAVAILABLE` rows with valid conversation identity are re-opened once by V41 so the real Vinted conversation can be inspected again.
- Offer ladders must increase in every pricing mode, with an additional runtime check before a next-step submit.

## Known safety choice

Configured chat messages remain best-effort after a confirmed price offer. If a message send is ambiguous, Flipbot does not retry it automatically because doing so could duplicate the message. Price offers remain guarded separately by persistent action guards/quota idempotency.

## Tests

Adds/extends regression coverage for:
- pending retention after elapsed time/read/seller chat,
- accepted/rejected/pending Vinted status variants,
- impossible seller counteroffer evidence,
- last-step seller counteroffer -> ACTION_REQUIRED,
- increasing ladders in non-adaptive mode,
- refresh-safe arbitrary Vinted navigation.
