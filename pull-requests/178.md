## Description

## Problem
The market observer already opens every unresolved Vinted listing sequentially, but some item pages still remained unresolved. Runtime showed 49/70 timestamps resolved on one catalog page even though all 70 detail pages were opened.

DevTools confirmed the live Vinted DOM uses an exact field:

`[data-testid="item-attributes-upload_date"] [itemprop="upload_date"]`

and for the one-week singular case Vinted can render the value literally as `tygodnia`, with no numeric prefix and no `datetime` attribute. The old generic `Dodane` text scan rejected that value.

## Changes
- Read the confirmed `item-attributes-upload_date` field first, before generic text/JSON-LD/hydrated fallbacks.
- Use `[itemprop="upload_date"]` as the value source and preserve a `datetime` value if Vinted provides one.
- Parse the confirmed singular `tygodnia` label as one week before the observation time.
- Keep the existing sequential detail-page navigation, 1.5 s pacing, 403/429 backoff, session-refresh handling, catalog restore and metadata fallbacks unchanged.
- Add regression tests for the exact selector and singular week label.

## Calendar semantics
No backend calendar change is needed. Existing planning already uses Europe/Warsaw, local midnight for Today, Monday 00:00 for the current week, and the preceding Monday-to-Monday interval for the previous full week.

## Scope
- Market statistics publication-time resolver only.
- No normal bot scheduling, negotiation, session, mobile or frontend behavior changes.
