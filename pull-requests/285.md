## Description

## Problem
When a bot had a persisted SESSION_BLOCKED cooldown, clicking "Wyświetl sesję" opened headed Chromium but scheduled work still respected the multi-hour cooldown. The window could therefore look idle even though the user explicitly opened it to solve CAPTCHA.

## Fix
- when LIVE preview starts for a bot with persisted SESSION_BLOCKED, wake its due scheduler work immediately
- bypass the persisted cooldown exactly once for that exclusive visible recovery attempt
- keep generic workers excluded while LIVE owns the account session
- normal job logic then surfaces/waits for CAPTCHA in the visible Chromium
- successful authenticated work clears the block through the existing runtime/session-success path
- if Vinted is still blocked, the bot returns to the normal exponential cooldown instead of retry-looping
- idle manual CAPTCHA recovery still saves validated storage state and immediately releases the cooldown
- runtime UI now explains that blocked LIVE mode is manual recovery and resumes automatically after CAPTCHA

## Safety
The button itself does not mark the session recovered. Recovery still requires positive authenticated evidence or a successful normal job. Existing session validation/last-known-good safeguards remain unchanged.
